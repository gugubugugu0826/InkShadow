## 1. 页面范围结论

当前真正包含用户界面的应用只有：

- `apps/desktop`：主产品界面，React + Vite + Tauri，使用 Hash Router；
- `apps/web`：独立的浏览器 Guest 加密写作单页，没有路由。

以下应用当前没有用户页面：

- `apps/cloud-api`：纯服务端 HTTP/API；
- `apps/android`：只有 `core` 与 `android-keystore`，没有 Activity、Fragment、Compose 或
  Android UI 模块。

Desktop 在 `apps/desktop/src/app.tsx` 中注册了 33 个明确路径和 1 个通配状态页。`/` 与
`/start` 显示同一个启动页。未知路径显示“页面不存在”、当前地址和返回项目列表入口，不再
静默重定向。

## 2. Desktop 入口与壳层

| 文件                                                           | 职责                                                               |
| -------------------------------------------------------------- | ------------------------------------------------------------------ |
| `apps/desktop/index.html`                                      | Vite HTML 入口                                                     |
| `apps/desktop/src/main.tsx`                                    | 挂载 React 根组件                                                  |
| `apps/desktop/src/app.tsx`                                     | 懒加载页面、注册路由、Feature Flag 守卫                            |
| `apps/desktop/src/appearance-preference.tsx`                   | 三态外观偏好、挂载前应用和系统变化同步                             |
| `apps/desktop/src/runtime-context.tsx`                         | 创建和注入 `DesktopRuntime`                                        |
| `apps/desktop/src/components/app-error-boundary.tsx`           | 捕获未处理界面错误，提供重试和返回安全入口                         |
| `apps/desktop/src/components/command-palette.tsx`              | `Ctrl/Cmd+K` 快速前往可用页面；支持键盘选择、Escape 关闭和焦点返回 |
| `apps/desktop/src/components/desktop-shell.tsx`                | 顶栏、导航、页面标题、在线状态和内容壳                             |
| `apps/desktop/src/components/desktop-persistence-boundary.tsx` | 路由和窗口关闭前刷新待落盘数据                                     |
| `apps/desktop/src/styles.css`                                  | Desktop 全局样式                                                   |

运行时有两种模式：

- `tauri`：正式桌面边界，使用 SQLite、系统凭据库、项目密钥、原生模型和文件选择器；
- `browser-development`：浏览器调试模式，部分能力使用内存或 `localStorage`，其余明确显示
  不可用，不能当作发行版数据层。

`AppShell` 只渲染一个 `<main>` 主地标。应用壳层锁定为视口高度，右侧主内容区独立滚动；
设置等长页面不会再被页面根节点截断。窄于 60rem 时，主导航变为抽屉：按钮提供
`aria-controls`/`aria-expanded`，打开后显示遮罩、圈定焦点并隔离背景，可用 Escape 或遮罩
关闭，关闭后恢复原焦点。

启动页、登录页和三条创建旅程不使用 `AppShell`，但会在视口内各自纵向滚动。这些页面在
矮窗口下使用安全居中，避免顶部内容因整页垂直居中而移出可见区。

`DesktopShell` 的常驻导航包括作品库、开书、任务和设置；社区模板和团队入口只在对应
Feature Flag 开启时显示。进入项目范围后，普通一级导航固定为正文、规划、设定、检查四区。
搜索、故事关联、从正文更新设定、素材、多智能体、微调、翻译/短剧和同步等能力通过页面内
“高级工具”或条件入口渐进披露。团队模板入口只在团队项目上下文且运行时可用时显示。

每次完整路由切换都会更新 `document.title`，并把焦点移到新页面的一级标题；设置页等页内
哈希导航由目标页面自行滚动并聚焦，不会被壳层重新抢走焦点。顶栏标题已覆盖素材、团队审阅、
团队模板及其他已注册路径。

`cloud-identity-auth-flow.tsx` 是登录页内部状态机，不是独立路由。URL 只承载页面位置，云会话
凭据由原生安全边界管理。

云会话检查失败不会再静默返回启动页。页面会说明本地项目仍可使用，并提供“重新检查”和“暂不
登录，继续本地使用”两条明确路径。

一句话开书在用户选择“保留开头，确认创建”后进入“都准备好了，看一眼全貌”摘要页。书名上限
120 字，故事摘要上限 4000 字；用户可返回继续调整，创建后得到本地项目、空白第一章和一条
`ready` 状态的 AI 建议版本。开头来自真实供应商时显示供应商与模型；未连接或调用失败时只标为
“本地草案（未调用云端 AI）”。用户明确采纳前，稳定正文保持为空；已有候选的章节、内容或状态
与当前旅程不一致时，创建流程失败关闭，不覆盖正文。

首次真实开头会先预置空项目、空章节和空不可变版本，再把生成结果提交为隔离 Candidate。Novel
Skill 默认不参与；只有作者已在项目“写作方法（实验）”中显式启用且当前开书任务适用时，才会在
同一 `context trace → generation → model invocation → Candidate` 链上保存采用/舍弃方法快照。

开书页在用户操作前明确说明将并发产生 3 次独立 Provider 调用、可能分别计费且不自动重试。
即时行动、人物对话、悬念线索三个槽使用不变的槽 ID，显示序号与身份分离；取消或其他槽失败不能让成功方案改号。
只有作者明确选择一个 `ready` 或允许
保留的 `partial` 方案后，才进入问题规划。0 个可用方案时只显示失败、重试、自己写和本地示例，
不显示问题卡；1 个可用方案也必须由作者明确选择，不能用“首个 ready”冒充作者决定。

问题规划读取原始想法、已选择开头、`ProjectSeed`、可证明的现有文本与已回答内容，输出有目的、
目标字段和来源的结构化缺口问题。默认最多 3 个核心问题，信息充分时可以为 0–2 个；结构化规划
不可用时切换到确定性基础引导。页面显示当前问题及为什么要问；作者可以返回、跳过或随时结束，
不会无限追问。回答和跳过只更新可恢复旅程与 `ProjectSeed`，不会自动重写已选开头或写入正式正文；
只有作者明确选择时，最多再执行一次“根据全部回答重写”。

真实供应商开头固定保留三个彼此隔离的槽位，分别从即时行动、人物对话和悬念线索角度并发生成；
每槽独立显示 `planned/dispatched/succeeded/failed/cancelled/ambiguous/not_dispatched`
生命周期、耗时、字数、重试、继续补全和保留动作。批次与请求 ID、旅程 revision CAS 会
阻止取消后或旧批次的迟到结果覆盖当前选择。`MODEL_OUTPUT_TRUNCATED` 只有在这个开书提案边界已
收到至少 160 个可见字符时才能成为显式 `partial` 草稿，并可继续补全或重新生成；普通正文、改写
和其他 Candidate 仍严格拒绝截断结果。取消前未越过 Provider 边界的槽结清为 `not_dispatched`；
已越界但无法确认结果的槽结清为 `ambiguous`。应用启动恢复只结清孤立状态，不自动再次发送；
账本、任务中心和当前卡片共用同一终态。

作者自然语言在页面、ProjectSeed 与开书服务边界统一使用 NFC；空白、过短、过长和控制字符错误
必须给出具体原因。每个同步或异步失败都要归入对应槽位，不能留下永久等待状态。

没有可用开书模型时，“去连接 AI”在当前页打开 `quick-ai-connection-drawer.tsx`。快捷列表当前
包括 DeepSeek、OpenAI、阿里云百炼/Qwen、火山方舟/豆包、Ollama、智谱 GLM 和自定义
OpenAI-compatible。能可靠列目录的连接使用真实模型目录；百炼、豆包、GLM 等需要账号模型或
Endpoint ID 的连接要求用户明确填写，并用不含作品内容的固定短句验证文本能力，不根据模型名
猜测。失败可返回修改、重试、返回模型列表改选或跳过。新 Key 先使用一次性 staging 凭据，
非秘密目录保存成功后才提交到正式系统凭据项；浏览器预览不会保存凭据。

三条创建入口都会维护同一类 `ProjectSeed` 创建输入：前提、类型、基调、人物、关系、世界、
冲突、风格、视角、禁止项、当前方向、初步大纲和改写规则。每个字段同时记录来源与
`confirmed`、`unconfirmed` 或 `skipped` 状态，因而 AI 推测、用户确认和主动跳过不会混为一谈。
项目创建前由可恢复旅程快照负责，项目创建后保存到项目自己的 `runtime.projectSeeds`；它不是
稳定正文，也不是已经确认的 StoryFact。

导入页只恢复历史上通过严格结构和原文位置校验的分析结果；这些模型提取仍位于统一 StoryFact
待确认队列，不直接修改正文或正式设定，事件继续使用 `causal_event` 候选格式。历史进度可查看
或跳过，但当前不会重试/新建 Provider 分析、试改或逐章生成；已有隔离 Candidate 仍可显式决定。
详细边界见
`docs/product-rebuild/05-PHASE-1-IMPORT-WORK-ANALYSIS.md`。

## 4. 项目、构思与市场

| 路由           | 页面文件                                              | 页面内容与主要操作                                                                                                                                                                                                                                                            | 条件与数据来源                                                                                                   |
| -------------- | ----------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| `/projects`    | `apps/desktop/src/pages/projects-page.tsx`            | 搜索；进行中、已归档、回收站标签；作者作品与“测试与示例”分区；作者／测试分类可逆，内置示例受保护，系统评测隐藏；新建、重命名、归档、恢复编辑、移入回收站、恢复；单条分类读取失败不阻断作品和正文；真正首次使用时显示“从想法开始/导入已有小说”，已有导入流程时显示已保存检查点 | 项目用例与 `runtime.repositories.projectDisplayIdentities`；导入检查点窄读 `inkshadow.import-rewrite-journey.v2` |
| `/ideation`    | `apps/desktop/src/pages/ideation-page.tsx`            | 引导开书、快速开书、活跃草稿；九步构思；保存、跳过、锁定、本地结构建议和最终原子创建项目                                                                                                                                                                                      | `runtime.story.ideationDrafts`、`ideationService`；结构建议由本地规则生成                                        |
| `/marketplace` | `marketplace-route-page.tsx` → `marketplace-page.tsx` | 已安装模板、在线目录、标题/作者/标签搜索、类型筛选、安装、更新、带可恢复性说明的卸载确认和结果反馈                                                                                                                                                                            | `runtime.marketplace`；远程市场关闭或离线时仍可查看已安装副本                                                    |

项目显示身份是内容无关的附属记录，只有作者作品、测试作品、内置示例和系统评测四类；作品名、章节名和正文都不是分类信号。旧项目缺记录时按“待确认的作者作品”读取。SQLite 创建、导入、开书和内容同步在项目事务中一并写入初始身份与首条历史；浏览器开发存储使用同一次可恢复写入。分类附属记录损坏不会阻止权威作品与正文读取，但分类写入会失败关闭并提示重试。

九步构思当前依次为：

1. 类型与基调；
2. 目标读者；
3. 核心创意；
4. 主角驱动力；
5. 世界骨架；
6. 关键角色；
7. 情节路线；
8. 开篇钩子；
9. 输出规格。

市场路由当前没有向 `MarketplacePage` 传入发布或举报回调，因此相关入口不会显示；这不是
“接口已存在即页面可用”。

项目的新建与重命名输入框会在 Enter 提交前检查中文输入法组合态，确认候选字不会误触发提交。
只有进行中、归档和回收站三个状态都为空时才显示首次使用入口；仅当前标签为空、搜索无结果，或
作品只在归档/回收站时，会说明真实状态并提供清除搜索、查看归档或查看回收站，不会伪装成全新
作品库。隐藏标签不会重复渲染当前结果。

归档、恢复编辑和恢复项目完成后会显示明确反馈。移入回收站前必须经过确认对话框，进行中作品
还可改为归档；确认移入后保留既有 30 天软删除周期、显示可恢复期限，并提供“撤销”。作品库的
导入流程卡只读取已经落盘的“已导入、分析完成数/总数、改写目标、试改、规则”检查点。文件读取
与安全解析的实时进度只在导入页显示，离开后不会推测或伪造百分比。

社区市场未启用、离线或加载失败时，搜索、类别等在线目录控件不可操作，已安装副本仍可查看和
使用。卸载本地副本必须先确认源模板下架后的不可恢复风险，完成后显示结果通知。

### 5.1 页面主要内容

`workspace-page.tsx` 是单项目首页。它不承载正文编辑，而是汇总项目状态并提供章节和各领域
入口。新建章节时可勾选“创建为私密章节”；该模式从首个稳定版本开始阻止云端投影，没有已验证
本地模型时，需要读取正文或全书资料的模型处理会安全停止。只要作品仍保留任一私密章节，远程
Embedding、Rerank、审稿、续写、改写、规划、连续提取和剧情试演都会在真实派发前按项目级
authority 失败关闭；纯本地关键词搜索、编辑、版本、备份和导出不受影响。

普通模式和专业模式的项目工作台都显示“待处理生成结果”。计数只包含用途为正文、状态仍为等待作者决定的结果，不把方向选项、生成中的内容、已使用、已放弃或已失效记录混入待办；有待办时可直接进入对应章节查看。

`project-search-page.tsx` 显示每条结果的关键词、向量、关系和规则评分。向量服务可能需要
远程发送内容，页面必须保留显式数据出口提示。

`project-graph-page.tsx` 同时提供图形和线性列表，确保关系数据在图形不可访问时仍可阅读。
图谱是可重建的派生投影，不应被当作唯一权威数据。

`authoritative-extraction-page.tsx` 只从稳定章节生成待审候选。候选不会因任务完成而自动写入
正式设定，必须经过人工决定。

`project-materials-page.tsx` 对来源、授权和引用证据进行结构化保存。删除与合并不能破坏已有
章节引用证据。

story-governance-page.tsx 的云端“章节摘要与长程记忆”和“故事变化识别”当前保持不可派发。
旧项目开关不再让手动保存、Candidate 接受、导入、版本恢复或历史回填发送正文；逐章重建/识别
按钮也保持禁用，直到独立授权、精确 Provider/model 披露、持久发送边界、歧义终态和幂等保护完整。

同页的通用“修改事实”、历史修订恢复和重复事实合并只对 structuredValue = null 的纯文本事实开放。

同页“快速维护故事设定”可把人物、关系、世界规则或人物说话方式的自然语言描述先整理为结构化
候选；候选字段和 AI 补充建议在确认前都不写入，无法可靠解析时退回手动表单。正式人物关系必须
同时引用两个可解析人物端点，自指或缺端点内容不会成为正式关系。导入只接受

校验与预览 → 解决冲突 → 确认导入”七步执行：先 dry run，显示精确字段路径和阻断/待确认问题，
再逐项选择合并、保留当前或新建副本。正式写入使用单一 SQLite 事务、幂等哈希和 revision fence，
成功后保留导入收据；撤销前会复核后续编辑与引用，发现依赖时失败关闭。旧开书留下的原始 JSON
人物卡或缺双端点关系只进入 legacy repair，原值保留在版本历史且必须逐条确认。

同页“AI 参考记录”列出最近 50 次上下文编译摘要，可展开采用/舍弃资料、来源、层级和估算预算；

补写影响、提升或丢弃；新的试演统一进入 `/projects/:projectId/graph`，先按确认因果链计算影响范围，
全部锁定规则无法纳入安全预算时不会调用模型。

同页“写作方法（实验）”展示 7 个 Core 与 5 个 Genre 定义。它们全部是 `EXPERIMENTAL` 且默认

关闭不会删除旧调用回执，也不会修改正文、StoryFact 或已接受版本。

### 6.1 编辑器内容

`editor-page.tsx` 是当前最大的前端页面，包含：

- 正常宽度使用填满可用视口的章节列表、正文、AI 助手三栏；章节栏和助手栏可独立收起，正文
  使用窄/标准/宽版心，三个区域各自管理溢出；
- 在 1024px 及以下切为单一正文主列，章节进入左侧 Drawer，AI 助手进入带遮罩的右侧对话式
  检查器；800px 下继续保持单列、工具栏换行和收紧内边距，不靠隐藏横向滚动条冒充适配；

- 稳定正文编辑和本地持久化；
- 自动保存、手动保存和离开前刷新；
- 中文输入法组合态保护；
- 撤销、重做、字面量查找与替换；
- 字体、字号、行距和版心偏好；
- 光标、选区和滚动位置恢复；
- 追加式章节版本历史和恢复；
- 崩溃恢复草稿；
- 普通/本地私密章节标记及独立隐私切换确认；
- 模型容量、路由、预算与生成前预检；
- 续写提供短、标准、长和 200–12,000 字自定义档位；按模型上下文窗口、输出上限、系统/协议开销和
  保守 CJK token 估算动态计算可用上下文，不用固定 Top-K 冒充长程预算；
- 生成前预检区分“可开始”“有提示但可开始”“暂时阻断”：价格未知、上下文上限未知和近似
  token 只显示提示，“使用安全默认值并开始”仍可用；真正阻断时可以关闭弹窗先手写，正文编辑区
  获得焦点，修复 AI 设置不会丢失当前章节、光标、选区和滚动位置；
- 生成任务取消、重试和失败恢复；
- 截断、取消或返回不完整可见正文时只保存“未完成”的隔离 Candidate，不写稳定正文；作者可继续
  补全、保留并比较、重新生成或切换模型。继续补全固定原基线版本，完整保留供应商已返回的可见文本；
  界面预览可在最后完整句处收束，实际续写以上一次原始尾部作为 assistant 上下文，并在线性时间内去除
  安全重叠；
- 生成前与“本次参考”显示本次真实采用/舍弃的上下文来源及实验 Skill；没有精确 Skill snapshot 时
  明确显示未使用，不根据项目开关推测历史调用；
- AI 候选隔离；
- “历史生成结果”只列出当前章节用途为正文且不再生成中的结果。等待决定、已使用、已放弃和已失效记录都可查看；已放弃和已失效记录只读，不会重新写入正文；
- 等待决定的结果自最后更新时间起满 30 天只显示“超过 30 天，仍保留”提醒，不会自动失效、接受、放弃或删除。作者明确选择“继续保留”时，状态仍为等待决定，只刷新 `updatedAt` 并递增 `revision`；SQLite 继续使用状态与修订号 CAS，旧界面不能覆盖较新的决定；
- 查看、继续保留或放弃历史结果都不修改正文或不可变版本；只有作者明确“使用这版”才进入既有原子接受事务；
- 选中 1–12,000 个 UTF-16 字符后填写一次具体改写要求；选区、当前不可变版本和原文
  SHA-256 在发送前后都要一致，结果只保存改写片段和原始选区锚点为 `polish` 建议版本，再进入现有 Diff；
- 每次候选生成后的本机重复度质量门禁；只对可证明的重复项给出警告，不伪造文笔、POV 或一致性分数；
- 建议文本可在隔离区编辑并保存，重开后仍是未采纳建议，不会先写正文；
- 保存建议、接受和拒绝都携带当前界面展示的 Candidate 修订号；另一窗口保存新版后，旧界面的
  修改或决定会提示版本冲突，不会接受用户未看过的文本；逐章导入草稿也持久保存其展示修订号；
- 旧逐章草稿缺少 Candidate 修订号时，单章重生成和整批重生成都会在模型派发前停止；批次的
  `candidateId + candidateRevision` 在生成返回后同步写入本机存储，写入失败会保留当前页可见指针、
  停止后续模型调用并保留中断恢复标记；
- 续写只允许插入生成时光标，选区改写只允许替换生成时选区；整章改写明确提供替换整章、追加章末、保存为新草稿和取消。旧完整文档建议继续兼容逐处接受、保留稳定正文和显式应用策略。

保存或接受时会把是否负责本地故事资料整理写入持久布尔字段；旧记录缺失时按关闭处理，worker
重启、人工重试和模式切换都不会读取执行时的当前模式来猜测。章节摘要与连续状态字段在新任务、
旧任务恢复、人工重试和 worker 启动时都被强制关闭；这些路径精确产生 0 次 Provider 调用。
生产 SQLite 的“使用这版”事务会同时提交正文、不可变版本、AI 建议草稿决定和可恢复任务登记；
任一写入失败则整体失败。页面只等待这项核心提交，不等待搜索、故事关联和设定整理真正执行；
派生失败也不撤销已经成功的正文和不可变版本。手动保存、导入和历史恢复不在此处外推为已具备
同样的任务登记原子边界。

作品只要仍保留任一私密章节，所有读取正文、StoryFact、因果关系或其他全书资料的 AI 操作都只允许
通过已验证的本地模型执行；真实派发前还会复核包含保留章节集合、当前版本、状态与隐私修订的项目指纹，
条件不满足时以 `PRIVATE_CHAPTER_LOCAL_ONLY` 停止并发送 0 字。切换为
私密模式会阻止待处理明文投影并移除尚未确认发送的同步任务，但不能撤回过去已经完成的外部
传输；本地记录中“0 条云端确认回执”也不是从未上传的证明。切回普通章节只允许未来按设置使用
联网 AI、同步与导出，不会立即发送正文，也不会制造新的正文版本。

首次进入 Model Hub 会从连接、正文任务路由、系统凭据库和本地模型目录生成一份权威快照；加载
完成前显示当前读取阶段，不把初始空 state 渲染成“未配置”或“没有模型”。多连接冷启动优先恢复
正文生成路由实际使用的连接；操作 generation 会忽略迟到的旧请求。系统凭据库、目录或刷新失败

删除凭据后，原连接保留历史审计并可就地重新绑定；作者也可明确退役原连接后新建同供应商连接。
退役项单独收入历史区，不混入普通选择、智能推荐或全局 ready；路由只能选精确 active connection/catalog entry。

顶栏、作品库、Model Hub 和任务推荐的全局状态只表示“基础连接/基础配置可用”。
“基础配置检查 10/10”复用真实派发的 connection、catalog、Provider/model、capability evidence、
credential summary、route/revision 和费用 resolver，但是无作品正文的检查，不代表当前章节已经通过隐私、
编译后上下文和本次 request profile 检查。当前章节的真实 preflight 在派发前运行；任一项失效都会
覆盖顶栏为“当前续写需修复”，指明任务、原因和修复入口，且不创建 invocation、Candidate 或费用记录。

“保存供应商与模型”“测试连接并发现模型”“验证写作能力”分别按当前动作的最小条件启用：
已保存在系统凭据库中的 `credentialRef` 与本次新输入且格式有效的 Key 都算可用，不要求重复填写；
价格、上下文窗口、能力确认、基础评测和任务分工不是保存或连接测试的前置条件。按钮不可用时会给出
对应字段和解决办法，但正常未连接初始态只显示一个中性引导，不把三个禁用原因并列成错误；只有
作者实际尝试的动作失败后才显示对应上下文错误。供应商预设可恢复默认地址与必要字段但不覆盖已保存密钥、连接、目录或路由；
从生成前弹窗进入 Model Hub 时会定位所需连接/模型和修复区，并提供返回原章节的入口。

Model Hub 页面一次只挂载当前选择的连接、AI 分工、模型评测或图片分区；切换普通设置时保留 Shell，
不会让全局 Suspense 或单个子页错误替换侧栏和顶栏。路由错误恢复只记录脱敏 route key、阶段、
错误分类、是否恢复和时间；不记录原始异常消息、文件路径、作品、Prompt、Key 或模型输出。浏览器
测试只能证明 Chromium 行为，WebView 是否重载仍须打包 Tauri 复核。

“验证写作能力”与快捷连接使用固定无作品内容、`64` token 的共享文本探针；DeepSeek 的探针策略
由 Provider Registry 禁用思考模式，不按模型名称猜测。截断前已经收到非空可见文本时，只在这个
探针边界保存 `partial` 失败诊断并提交文本能力；只有推理或空文本仍失败，普通正文生成继续严格
拒绝截断结果。Settings 两个固定、无作品内容的 probe 入口已把点击时表单、精确目标和
content-free SHA-256 authority 绑定到同一 prepared input，并在生成前复核；四类漂移为 0 call，
成功精确 1 call。豆包 Endpoint ID 非空时优先作为唯一有效模型，同一值进入普通披露、授权、
catalog/connection 保存和实际派发；设置页聚焦 55/55 PASS，Provider dispatch surface 无剩余
P0/P1。首次成功且当前不存在任何任务路由记录时，智能推荐可建立 16 类文本任务分工；
旧版本若曾在第 16 项中断而留下纯自动、同方案的 15 类分工，也会以同一原子计划安全补齐。任一
用户建立的启用、禁用或自定义分工都不会被覆盖；结构化输出、Embedding、Rerank、图片和视觉等
其他能力继续等待各自证据。方案提交不把价格、上下文长度或本地基础评测等可选元数据误当成文本
路由前置条件；SQLite 写入失败会保留完整旧方案并提示重试，不再留下半套分工。诊断下载会列出最近
脱敏 AI 失败和 request ID，但不含作品、
Prompt、模型回答、推理正文、原始供应商错误或凭据。schema v3 保留 schema v2 对旧兼容指标的
明确命名，并新增 `modelHubUiSnapshot`、`recentModelHubActions`、`currentSessionStartedAt`、
`currentSessionErrorCodes` 和 `historicalErrorCodes`。旧兼容指标继续命名为
`legacyModelProfileCount` / `legacyModelProfilesWithSelection`，并单独报告 Model Hub 的连接、可用
连接、目录条目和启用路由数量，避免再把兼容档案数误读为 Model Hub 连接数。

DeepSeek 只在官方端点和精确官方模型 ID 命中时使用有有效期的官方资料 fallback；它低于真实目录
证据，且始终标记 `verifiedByInkShadow=false`，自定义端点不会继承。结构化输出必须通过固定严格
schema 探针；翻译必须通过不含作品内容的 `inkshadow.translation-probe.zh-en.v2` 后才写能力证据和
路由。Provider 推荐只给已连接目录项排序或显示带有效期的发现方向；阿里云
`text-embedding-v4` 等推荐不会自动创建模型、能力证据或任务分工。

2026-08-13 当前工作树已实现“官方可选目录”和“先选模型、再连接、返回原任务确认”的本地 UI
切片。它不会把供应商文档条目写入现有 `model_catalog_entries`，因为后者只表示某个真实 connection
已经同步/确认的账户目录；官方发现候选保存在独立、版本化、带更新时间和 31 天失效时间的 registry。
默认折叠的全局浏览器按国内、海外、本地分组，22 项任务各自也可展开候选；账户真实目录始终排在

- `routable_after_verification`：当前连接器和协议已实现，连接后仍须以账户真实目录与能力证据确认；
- `special_connection_required`：官方存在，但当前预设不能直接使用相应账号/Endpoint；
- `protocol_not_implemented`：官方存在，但 InkShadow 当前没有该任务协议；
- `discovery_only`：只有供应商发现方向，不能声称精确可路由模型。

## 13. Web Guest 单页

入口：

- `apps/web/index.html`
- `apps/web/src/main.tsx`
- `apps/web/src/bootstrap.ts`
- `apps/web/src/app.tsx`

Web 没有路由，页面由状态切换：

1. 首次显示风险确认对话框；用户可接受，也可拒绝并保持正文和密钥未载入，随后重新查看风险
   说明；
2. 锁定工作区允许创建加密项目、从 `.encrypted.json` 加密副本恢复、查看完整密文项目标识、
   输入恢复材料解锁和下载密文副本；
3. 加密副本导入上限为 32 MiB；文件、严格 schema、信封绑定、恢复材料和解密后领域数据全部
   验证成功后才写入 IndexedDB，失败不保留部分项目；
4. 创建时只在页面内存显示一次性恢复材料，用户可复制或下载带项目名称、完整项目标识和创建
   时间的恢复文件，确认已经另存后才提交密文项目；
5. 解锁后可编辑章节、保存新的 AES-256-GCM 密文版本、立即锁定和下载密文副本；有未保存修改
   时，手动锁定会要求保存后锁定或明确放弃；
6. 页面隐藏或离开触发自动锁定时，会先尝试正式保存和仅含密文的临时恢复草稿，再清除可见
   正文和会话密钥。正式保存失败但临时密文成功时，下次用恢复材料解锁会自动恢复并标记为
   未保存；两种写入都失败时显示明确警告；
7. 能力面板明确说明不支持云同步、团队协作、明文外发和桌面 SQLite。

状态来源：

- `apps/web/src/application/guest-workspace-service.ts`

项目名、章节标题和正文加密后才进入 IndexedDB。项目密钥和恢复材料只存在于当前页面内存；

## 15. 静态代码不能证明的事项

- 路由存在不等于发行构建已开放对应功能；
- `navigator.onLine` 不等于 Cloud API 或模型端点可达；
- 市场目录、成员、用量、审阅、模板、模型和更新内容必须由真实服务返回；
- 文件选择器、备份恢复、系统凭据库、剪贴板和窗口行为必须在目标平台运行确认；
- 云页面还会受登录、角色、assignment、密钥版本、设备授权、订阅和服务端修订影响；
- 所有 Desktop 页面均为懒加载，并受数据库迁移完整性门禁影响；
- 初始化或迁移失败时直接显示“无法启动墨影”，不会进入普通路由；
- 浏览器运行验证不能替代 Windows/Tauri 打包版对滚动、窗口和原生焦点行为的最终复核；
- 当前安全更新链路没有安装执行器；下载校验成功仍需按已验证的官方发行说明完成后续安装。
- 页面、单元测试和本地 SQLite 验证不代表真实供应商凭据、远端模型或长篇端到端流程已经验收；
- 私密章节门禁只能阻止当前及未来由 InkShadow 发起的发送，不能证明或删除此前已到达第三方的副本。
- 当前工作树迁移上限为数据层 `0077` / 原生层 `80`（77 个数据迁移 + 3 个故事核心迁移）。`0071`
  已随 `v0.2.6` 冻结；`0072` 区分正文与方向结果，`0073` 保存用户故事资料修订，`0074` 保存不可变
  版本的本地整理责任，`0075` 保存生成尝试的隐私快照与同一次调用标识，`0076` 收窄本地事实的作者修订触发器，`0077` 保存内容无关的项目显示身份和不可变修订历史。启动恢复按模型服务发送边界
  结清调用账本和运行记录，把仍非终态的任务对账到终态，并且不自动重发。同一变更集继续复用 `0045`
  派发租约与隔离结果／上下文输出的原子版本围栏。旧页面说明中的较低数字只属于历史快照。当前恢复
  合同覆盖 174 张作者数据表，另有 1 张内容无关的原生项目派发租约表明确不恢复；旧备份可同时缺少身份当前表和历史表，只缺一表时失败关闭；计划调用标识随调查
  步骤整表恢复。原生命令数量与迁移数量不能混用。
