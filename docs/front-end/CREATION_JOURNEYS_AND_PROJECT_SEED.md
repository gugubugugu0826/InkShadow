三条创建入口使用同一个 `ProjectSeed` 契约，但界面继续使用各自的任务语言。

| 入口           | 用户流程                                                 | 创建前恢复                           | 项目创建后持久化                           |
| -------------- | -------------------------------------------------------- | ------------------------------------ | ------------------------------------------ |
| 从一个想法开始 | 一次一个问题，可选择、自定义、跳过、返回、重新生成或保留 | `creative_journeys` 快照与 turn 历史 | `project_seeds` / 浏览器 ProjectSeed store |
| 导入小说       | 导入、分析、目标、试改、规则、逐章处理                   | 导入旅程本地草案                     | 目标和规则变化后按项目持续写入             |
| 专业创建       | 项目名必填，其余设置渐进展开                             | 专业创建恢复记录与未完成项目指针     | 项目创建后、补齐工作区前写入               |

ProjectSeed 是创建输入，不是正文。任何 AI 文本仍必须进入“AI 建议版本”（Candidate），用户接受前不得覆盖正文。导入原文不会复制到 ProjectSeed。

“从一个想法开始”必须先得到至少一个可用开头，并由作者明确选择后才进入提问。选择完成后，
确定性缺口规划器只运行一次：它根据原始想法、已选择的开头、当前 `ProjectSeed` 与可证明的现有
文本区分已知、缺失、模糊和冲突字段，并一次生成最多 3 个问题；信息充分时可以是 0–2 个。页面
显示当前问题、提问目的和受影响字段；作者可返回、跳过或随时结束。回答只更新既定问题对应的
`ProjectSeed`，不会追加新问题、隐式重写已选开头或触发第 4 次 AI planner 调用；只有作者明确
操作时才执行一次整合重写。

点击生成前必须明确披露将并发 3 次独立 Provider 调用、可能分别计费且本操作不自动重试。
合法生成批次的预期调用数精确为 3；作者选择开头和回答既定问题的调用数均精确为 0。
三个开头槽使用稳定 slot ID，显示序号与身份分离，并分别投影
`planned`、`dispatched`、`succeeded`、`failed`、`cancelled`、`ambiguous` 或
`not_dispatched`。显示层可再把成功分为 `ready/partial`，但不得丢失真实 dispatch 边界。0 个可用方案时不
显示问题卡或创建动作；1 个可用方案时允许作者明确选择该方案并继续；取消不移除已成功槽或重编号，
旧批次迟到结果只进入历史，不得覆盖当前选择。作者自然语言统一使用 NFC，输入失败要显示具体字段与原因，
并在 Provider 边界前结清为 `not_dispatched`。已越过边界但无法确认结果的槽必须结清为 `ambiguous`，
应用启动恢复只结清状态、绝不自动再次发送。

当前实现不会因第一个本地持久化错误提前结束整个批次：它等待三个槽各自完成后再汇总，已成功
方案保持可选，明确失败单独归档，发送后无法确认的方案显示“结果待核对”。页面只有在三个槽都
进入可解释终态后才结束本批操作；重启读取相同槽标识和调用记录，不为已发送槽创建新请求。

权威状态顺序为：

```text
创作输入
→ 输入校验
→ Proposal Batch
→ 3 个独立 Slot
→ 作者选择 Proposal
→ Deterministic Gap Planner（一次，0–3 问）
→ ProjectSeed Candidate
→ 创建项目/空章节/空不可变版本
→ 隔离 AI Candidate
```

禁止组合：`0/3 可用 + guidance`、`没有 selectedProposalId + planning/guidance`、同一槽存在两个终态、取消后仍 `running`、旧 batch 结果写入当前 batch、回答问题自动写正文或自动重写开头。输入预检失败发生在
创建 journey、空项目和任何 Provider 请求之前；已进入合法批次后的每槽故障则必须单独收敛，不能把
另外两个成功槽视为失败。

Deterministic Gap Planner 的输入至少包括 `originalUserIntent`、`selectedOpening`、可证明的
`existingText`、当前 `ProjectSeed`、人物/关系/世界规则、写作偏好、已知 POV/类型和未决问题。
它一次给出 `known`、`missing`、`ambiguous`、`conflicting`、`optional` 与 0–3 个问题，不读取模型
路由，也不在回答后再次运行。既定问题结束后由作者选择保留当前开头、显式重写一次或直接创建；
当前流程没有第 4 问或额外 AI planner。

字段状态语义必须保留：

- `confirmed`：用户明确给出；
- `unconfirmed`：尚待确认或弱推断；
- `skipped`：用户主动跳过。

页面不应把空白、跳过和 AI 推测显示成同一种状态。存储失败时不得假装保存成功，也不得因此修改稳定正文。
