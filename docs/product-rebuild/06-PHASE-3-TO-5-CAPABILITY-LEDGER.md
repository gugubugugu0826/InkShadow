## 1. 状态定义

| 状态     | 含义                                                                                                     |
| -------- | -------------------------------------------------------------------------------------------------------- |
| 已闭环   | 有真实运行入口、持久化或明确的只读结果、错误处理和自动化测试；用户可完成该能力承诺的全部当前范围         |
| 条件可用 | 真实调用链已经存在，但依赖用户启用、确认的结构化证据、已验证模型能力、凭据或特定协议；条件不足时明确跳过 |
| 部分闭环 | 只实现了能力中可证明的一部分，并在代码和界面中如实限制声明                                               |
| 待实现   | 没有用户可完成的真实调用链，或实现尚未接入运行时、页面和验收测试                                         |

## 2. 总体结论

- Phase 3 已有受控的“稳定正文 → 持久任务 → 状态生产 → 严格投影 → 检查/上下文消费”链路。接受 AI 建议、接受导入改写或追加式恢复历史版本后，都会先保留稳定正文，再登记搜索、摘要、故事变化和故事关联任务；派生失败不会回滚正文。
- Tauri 运行时使用专用到期查询补跑任务，任务中心可对合法失败执行一次“立即重试后台整理”。重试动作把规范失败阶段、任务序号和尝试次数原子绑定到不含正文的持久恢复标记；即使进程在排队后、执行前退出，重启也只恢复该次失败阶段，旧尝试不能覆盖新状态。旧作品还可先预览零写入回填计划，再明确确认当前稳定版本的缺失任务。自动保存仍不会调用模型；项目未启用对应路由或没有可用模型时明确跳过，不伪造摘要或事实。
- 连续提取的可选投影不会被直接信任。投影适配器重新校验项目、章节、不可变版本、内容校验值、UTF-16 原文范围、分支、当前性、确认与锁定状态；已失效事实一律排除，章节范围自动投影还必须匹配当前版本和内容哈希。同一实体、事实类型和替换键只选取最新有效投影，较旧投影以明确原因留在舍弃审计中。
- 非演示续写会经过固定十二层编译。三条创建旅程写入的 ProjectSeed 中，仅作者确认的字段会成为硬规则、当前任务、人物状态、世界设定或场景目标；未确认的导入分析和 AI 推测不会进入上下文。当前章节片段使用原始稳定正文中的绝对 UTF-16 起止位置并绑定当前内容哈希。POV 派生资料只有在调用方同时提供经确认的当前 POV 人物和叙事序号时才参与筛选；当前生产流程尚无这组确认元数据，因此默认不推断 POV，相关层为空并保留诊断。当前版本章节摘要可进入“最近事件”层；用户可在生成前查看选择/舍弃，也可在“设定 → AI 参考记录”查询最近 50 次内容最小化历史。
- Rerank 不再只有本地路径。用户在专家分工中明确允许发送候选片段后，可通过已验证的阿里云百炼/Qwen 北京地域 OpenAI-compatible `/reranks` 协议重排；任何门禁或调用失败都保留完整的本地确定性顺序。
- Phase 4 仍保留确定性检查作为可信主路径；另有分栏、只读的 AI 语义矛盾、POV、人物声纹和内容质量复核。模型结果必须通过严格 JSON、证据白名单和返回后复核，并始终标记“需要人工判断”。
- Phase 5 已加入可审阅 AI 剧情规划：用户按需生成全书方向或章节场景拆解，结果先进入独立规划候选，只有明确采纳才更新目标大纲节点简介。它不是自动后台持续改大纲。
- 跨阶段外观已提供“跟随系统 / 浅色 / 深色”三态，本机保存并在应用挂载前应用；它不改变正文、数据库或云状态。

### 3.1 非演示续写真正会使用的资料

1. ProjectSeed 中作者确认的禁止项，以及用户确认并锁定的 StoryFact（必选硬规则）；
2. 本次写作任务和 ProjectSeed 中已确认的类型、基调、风格、POV、改写规则（必选）；
3. ProjectSeed 中已确认的冲突、当前方向、初步大纲，以及其他可选场景目标；
4. ProjectSeed 中已确认的人物、关系、世界和创作起点；
5. 合格 StoryFact 映射出的人物状态、事件、伏笔、世界和人物语言资料；只有调用方同时提供经确认的当前 POV 人物与叙事序号时，才纳入符合人物、取得顺序和生效区间的 POV 资料；
6. 当前已保存章节最多约 12,000 个 UTF-16 代码单元的尾部；
7. 当前版本、可撤销的章节摘要；
8. 主分支已验证因果图中最多 8 个本地候选；
9. 仅在本地 Ollama 向量 ready 时取得的语义候选；
10. 本地确定性证据重排，或满足全部门禁时的百炼/Qwen 远程重排；
11. 用户启用的可见写作偏好（最多 24 条）。

缺少合格事实、摘要、向量或远程重排时，对应层为空或降级，并不代表检查通过，也不会阻止其他安全层继续工作。当前生产调用方没有经确认的场景 POV 与叙事序号，因此 POV 派生层按合同为空；不得从 ProjectSeed、章节标题或模型推测补齐。

## 6. 数据与安全不变量

- 新增本地迁移已连续追加到 Data `0056` / Tauri `59`：`0052` 保存连续状态提取的精确路由完成收据；`0053` 为反馈事件增加发生时学习策略与自定义反馈哈希簇；`0054` 增加明确反馈的项目级幂等身份；`0055` 允许合法历史版本回执恢复，同时继续核验项目、章节、不可变版本归属与内容哈希；`0056` 只向现有 Model Hub 能力扫描和调用事实追加可空、脱敏的失败诊断字段与查询索引。全部采用只向前迁移，没有改写旧 migration。
- 连续状态与章节摘要复用 StoryFact；连续提取路由完成回执保存在 `continuous_story_state_route_receipts`，并纳入一致性备份恢复。新提交仍在事务内复核当前版本和内容哈希；同一人物的不同关系对象使用已确认目标实体和关系属性形成独立替换身份，不能互相退休，目标缺失或证据不匹配时失败关闭。同一不可变版本内如果模型为同一个替换身份返回多条变化，提交前按原文证据位置和稳定语义顺序确定性折叠为最后一条，重试不会重复付费或重复写入。规划候选单独保存在 `story_planning_candidates`，三条创建旅程共享 `project_seeds`。当前共有 142 张应用表；恢复契约复制其中 141 张权威表，并在同一事务内清空 4 个可重建派生根表；不含用户内容的 1 张临时远程派发租约表明确不恢复。恢复不会覆盖章节、不可变版本或正文 AI 建议版本。
- 章节隐私使用项目级 `local_only` authority：只要项目仍保留私密章节，读取全书资料或章节正文的 AI 操作只能使用已验证的本地模型。项目上下文远程 generation、Embedding 和 Rerank 在原生 `BEGIN IMMEDIATE` 事务中重新读取项目与活动/回收站章节，精确复核集合、状态、当前版本、章节修订、隐私修订和跨语言固定指纹；复核成功后，从派发前直到网络成功、失败、取消、超时或 panic 真正结束都持有内容无关租约。租约期间只阻止新增/转入 `local_only` 与删除项目，普通正文、版本和自动保存仍可写。Renderer SQL bridge 不能读取或修改租约；`non_project` 仅保留固定、无既有项目内容的连接/能力探针和建项前创意开头。项目导出默认排除私密章节，只有显式选择才包含。
- 章节摘要、连续状态和远程重排默认不会因自动保存运行。界面明确说明可能发送的内容、最多调用次数和费用；远程重排还要求显式远程内容同意。
- 模型密钥只从 OS 凭据库的版本化 owned 槽读取，不进入 SQLite、日志或调用账本；旧模型档案槽仅兼容读取。连接提交 journal 只保存槽引用和恢复阶段，启动恢复不会删除任何仍被已发布连接引用的当前槽。账本仅记录供应商、模型、任务、Token/费用等元数据。
- 连续提取、检查、What-if、多 Agent、规划和图片输出都不得直接改写正文。重大事实需人工确认；规划需明确采纳；生成正文继续使用 AI 建议版本隔离。
- 外观偏好只写本机 `localStorage`；跟随系统时根节点不强制主题属性，编辑纸张可保留自己的阅读表面。

## 7. 验证证据与不可替代边界

当前工作树有覆盖以下链路的定向自动化：

- 连续提取、章节摘要、严格投影，以及投影进入确定性验证、声纹/POV 和叙事分析的跨服务测试；连续提取还覆盖持久回执重启去重、零候选完成、同事务退休/修订/插入/回执和注入故障全回滚；
- 上下文编译、摘要来源筛选、内容最小化 trace 和历史面板组件测试；
- 百炼/Qwen 远程重排的 Model Hub 服务、前端原生客户端、Rust 网关/协议和本地回退测试；
- AI 模糊复核、内容质量、检查页分栏和候选重复质量关卡测试；
- AI 剧情规划服务、候选 store、SQLite 迁移、页面编辑/拒绝/整体采纳、字段/行级选择性采纳、空选择、重复请求幂等和并发冲突测试；
- 实体别名允许列表消歧、畸形 payload 失败关闭、POV 知识取得链、确定性检查快照，以及旧作品回填计划/过期指纹/限流测试；
- 三态外观初始化、持久化、系统变化和设置页入口测试。
- 已接受版本派生任务的幂等登记、启动补跑、人工立即重试、重试序号/尝试 authority、进程重启后的阶段恢复、损坏恢复标记失败关闭、导入/恢复来源和关闭顺序测试；
- ProjectSeed 仅确认字段进入真实续写编译、未确认推测被排除，以及来源/预算 trace 测试；
- 私密章节远程发送门禁、原生派发租约的双连接写入顺序、协调/新获取确定性竞态、命令 Future 丢弃、取消/超时清理、TS/Rust 固定指纹、项目搜索探针碰撞、Renderer SQL 隔离、备份不恢复租约、默认导出排除、EPUB 导入/导出和每日自动备份安全清理测试。
- 文本能力探针的供应商策略、64-token 预算、可见截断/推理-only 边界、原生 SSE 推理与正文分离、
  能力证据、初始文本分工、评测前置路由及 schema v2 脱敏失败诊断路径；这些受控测试仍不能替代
  使用真实 DeepSeek 凭据、账号配额和目标 Windows 网络的线上验收。

历史候选曾运行过全仓、Rust、production E2E 和未签名 NSIS 检查，但这些结果只绑定当时的
提交/工作树。当前最终数字、失败和制品哈希必须从 `docs/execution/TEST_RESULTS.md` 与

## 8. 当前仍未达标的总清单

1. 自动保存或后台无感扫描全书的持续状态维护；当前仅项目选择启用后的手动保存和显式重建。
2. 跨章节别名冲突已有人工允许列表消歧，POV 取得链已有严格投影；仍缺经用户确认的当前场景 POV/叙事序号入口、覆盖全书自然语言的自动稳定实体识别、完整知识状态维护和安全自动因果边提取。

4. 供应商精确 tokenizer 和百万字级上下文/索引性能、质量、费用基准。
5. AI 模糊与内容质量复核的真实供应商、标注语料准确率和误报/漏报验收。
6. 自动持续剧情规划；当前是用户按需生成、编辑并明确采纳的候选闭环。
7. 规划候选已有当前简介/结构化条目 Diff 与字段/行级选择性采纳；仍缺把条目安全映射为真实书/卷/章子节点，以及由新正文触发的可审阅重规划。

9. 正式签名安装包和目标 Windows 环境下的完整升级/回滚验收。
