## 1. 执行顺序

### Phase 0：真实审计与基线

交付：本目录四份文档、现状分级、新旧信息架构、三条流程、数据复用/迁移、验收与回滚。

完成定义：所有“已完成”判断都有代码、调用链、用户闭环和当前测试证据；历史状态标签不继承。

### Phase 1：新手核心体验

实施切片：

1. 新首页、最近创作和三个核心入口；
2. 一句话开书状态机、单问题引导、可恢复会话和开头 AI 建议版本；
3. 导入分析、目标选择、代表性试改、Diff、规则确认和逐章候选任务；
4. 专业创建的渐进式配置；
5. 四区工作区和统一 AI 创作助手；
6. 普通术语映射、专家模式、首次示例、空状态和可操作错误；
7. 当前工作树全量回归和发布构建 E2E。

Phase 1 验收：

1. 从打开软件到获得第一段可修改内容不超过三个主要操作；
2. 只输入一句话即可开始；
3. 一次只问一个问题，同时提供选项、自定义和跳过；
4. 可返回、修改、重新生成、保留并恢复上次流程；
5. 普通界面不要求理解世界书、Embedding、GraphRAG 或提示词；
6. 导入后可直接描述改写目标，批量前必须先试改；
7. 原文和稳定版本不被静默覆盖；
8. 项目一级导航只有正文、规划、设定、检查；
9. 空页面有下一步，错误告诉用户原因和解决办法；
10. 没有无效果按钮；自动化 E2E 覆盖三条入口和恢复。

### Phase 2：InkShadow Model Hub

实施切片：

1. Provider Registry 与首批供应商预设；
2. 一次连接、系统凭据库和普通/专家字段分层；
3. 连通检查、模型同步、目录持久化和可理解结果；
4. 能力证据模型与轻量探测；
5. 小说任务目录、主/备用模型、参数/费用/隐私/失败回退；
6. 智能推荐、高质量、经济、本地隐私、完全自定义方案；
7. 调用事实记录、错误恢复和单能力降级；
8. 迁移、端到端测试和文档同步。

Phase 2 验收：

1. 一个供应商只连接一次，密钥不重复填写；
2. 可测试连接、同步模型并重新同步；
3. 能力来自供应商证据、预设、探测或用户确认，不只猜模型名；
4. 普通用户一键配置方案，高级用户可覆盖；
5. 每项小说任务可选主模型和备用模型；
6. 失败提示可理解，单项能力失败不阻止基础写作；
7. 每次调用记录供应商、模型和任务，但不记录正文、Prompt 和密钥；
8. 旧模型配置无损迁移，旧生成链仍可回退。

### Phase 3：统一故事状态与上下文

交付：统一事实、候选事实、实时人物/世界状态、多粒度本地 FTS、可选 Embedding/Rerank 底层协议、
分层上下文编译、来源与 Token 说明、可重建索引。

门禁：默认正文生成必须读取已锁定规则、当前任务、POV 知识、近期事件和证据；运行记录可解释
每个上下文项为什么进入或被舍弃。

### Phase 4：小说智能验证

交付：因果事件图、确定性矛盾、世界规则、POV、声纹、多线叙事、伏笔、节奏和质量关卡。

门禁：每个问题有明确类型、原文、冲突事实、证据、严重程度和决定动作；无证据不得报冲突。

### Phase 5：高级 AI 能力

GraphRAG、试演另一条剧情、深度审稿、自动规划、反馈学习、图片和模型评测统一读取 Phase 3–4
状态与证据，不建立平行真相。

### Phase 3 当前验收边界

- 非演示模式的“继续创作”确实运行十二层编译器，不再只发送标题和整章正文；本地演示生成不作为外部调用验收样本。
- 锁定规则和当前任务是必选项；二者超出预算时在模型调用前失败。
- 当前章节、合格 StoryFact、当前版本章节摘要、确认因果候选和启用偏好会进入真实编译；active continuation 使用有界多查询 FTS 与 StoryMemory，当前不会自动运行 embedding 或远程 rerank。
- 接受 Candidate、接受导入改写、恢复历史版本、手动保存和旧作品回填共享同一条本地-only 派生管线：摘要/故事状态标记在登记、人工重试和启动恢复时都被强制关闭，即使旧任务元数据曾要求运行也会先被清洗；Provider 调用上限精确为 0。
- 连续提取的服务层仍只允许保存带不可变版本、校验值和精确 UTF-16 原文范围的可撤销或待确认事实，重大事实必须确认；但当前生产 UI 的“重建摘要/重新识别最近一章”等直接云操作已停用，不会派发。未来恢复前必须先完成独立授权、精确 Provider/模型与费用披露、取消、结果不明确和幂等合同。严格投影缺字段、越项目/分支、证据失效或权威不足时仍会跳过并留下诊断，不根据自然语言自行补字段。
- 当前通用用户修改、历史版本恢复和重复事实合并只适用于 structuredValue = null 的纯文本 StoryFact。结构化事实和因果事实不走纯文本重写或通用合并，只开放不破坏结构的证据查看、固定、删除与删除恢复；需要改变结构时必须使用对应的结构化事务。
- 用户可以在本次生成前查看选择/舍弃、来源和估算用量，也可以在“设定 → AI 参考记录”浏览最近 50 次不含正文、Prompt 和模型回复的历史记录。
- 远程重排底层协议与门禁仍保留，但普通搜索页的向量重建/查询嵌入入口已安全关闭，当前 production 默认为简单 FTS。未来若有可达远程重排动作，必须先披露精确 target、候选片段、调用数、0 retry、费用与隐私并明确确认；否则不派发且保留本地确定性排序。
- 因此“上下文编译、现有合格投影的严格消费与接受后的本地派生主链路”可验收；“当前用户可派发的云端摘要/连续状态生产”以及“无感全自动长程状态维护全部完成”均不可验收。

### Phase 4 当前验收边界

- 有结构化、用户确认且精确证据通过的输入时，检查页会给出问题类型、双方证据、严重程度和处理动作。
- 缺证据时明确返回 `skipped`，不能把空结果写成通过。
- 检查只读；忽略/允许/更新设定通过 StoryFact 决定记录，不静默修改正文。
- 声纹、POV、多线和节奏的确定性路径可读取严格投影形成的结构化证据；缺失或不合法投影仍会明确跳过。
- 旧“AI 模糊复核”和“AI 内容质量建议”批量 Provider 入口已安全关闭，配置 Model Hub、route 或 credential 也不会派发；页面保留关闭说明和历史兼容数据。
- 需要模型参与时使用有界一致性调查：先做 0-call 准备并精确披露目标、范围、去向、费用、1 call/0 retry，再明确确认；finding 只读，修复是单独披露的隔离 Candidate 动作，不自动修改正文或设定。

### Phase 5 当前验收边界

- What-if 必须先固定因果影响范围，模型不能引用范围外事件，结果只能进入沙盒分支。
- 写作偏好可见、可改、可停、可删、可清空；系统只依据显式重复意见形成偏好，不暗中分析正文。
- 本地模型评测只代表两条基础指令/结构探针和延迟，不代表文学质量。
- 多 Agent 仍是默认关闭的高级工具；统一上下文已接入不等于每次写作都会运行所有 Agent。
- 大纲页已有按需运行的“AI 剧情规划”：可生成全书方向或章节场景拆解，先保存为可编辑、可拒绝的规划建议；明确采纳时只更新目标大纲节点简介，并用基线修订阻止覆盖并发修改。它不是自动后台规划器。
- 图片生成只在桌面端、有效 `image_generation` 能力证据、ready 连接、隐私确认和
  OpenAI-compatible 协议同时满足时开放；当前只安全另存 base64 PNG，不自动写入正文或素材库。

### 跨阶段体验与外部验收边界

- 设置页提供“跟随系统、浅色、深色”三态外观，本机记忆选择并在 React 挂载前应用；这不涉及正文、数据库或云同步。
- 启动、登录与三条创建旅程等无壳页面已在视口内独立滚动；窄窗口下使用安全居中，避免顶部或底部主操作被裁掉。
- 连续提取、章节摘要、旧批量模糊/内容质量复核和普通搜索向量重建虽然保留服务层或历史合同，但当前生产入口停用，配置 Model Hub 或已有凭据也不会授权发送正文；未来恢复时还必须增加独立授权与派发恢复合同。剧情规划和图片生成等仍可达外部动作要求用户自行提供有效凭据、完成 Model Hub 配置并通过各自精确披露；没有凭据或真实服务时，只能验收失败关闭与本地降级，不能写成真实供应商已验证。
- 单元、组件、Rust 模拟协议和构建测试不能替代百万字级项目的召回率、延迟、内存、费用和长期稳定性测试。
- 发布安装包仍需在目标 Windows 环境完成首次安装、启动、升级、卸载保留、重装、数据库迁移和恢复演练；未完成前不得把工作树测试写成安装包验收通过。
