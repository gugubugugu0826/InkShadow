# 实施计划、验收标准、风险与回滚

> 文档状态：`AUTHORITATIVE_CURRENT`  
> 应用版本：`0.2.2`；设计基线：`DESIGN v0.3.1b`  
> 阶段“已接线”不等于 `VERIFIED`；最终证据必须绑定当次干净提交与制品。

## 1. 执行顺序

### Phase 0：真实审计与基线

交付：本目录四份文档、现状分级、新旧信息架构、三条流程、数据复用/迁移、验收与回滚。

完成定义：所有“已完成”判断都有代码、调用链、用户闭环和当前测试证据；历史状态标签不继承。

### Phase 1：新手核心体验

实施切片：

1. 新首页、最近创作和三个核心入口；
2. 一句话开书状态机、单问题引导、可恢复会话和开头 AI 建议版本；
3. 导入分析、目标选择、代表性试改、Diff、规则确认和逐章候选任务；
4. 专业创建的渐进式配置；
5. 四区工作区和统一 AI 创作助手；
6. 普通术语映射、专家模式、首次示例、空状态和可操作错误；
7. 当前工作树全量回归和发布构建 E2E。

Phase 1 验收：

1. 从打开软件到获得第一段可修改内容不超过三个主要操作；
2. 只输入一句话即可开始；
3. 一次只问一个问题，同时提供选项、自定义和跳过；
4. 可返回、修改、重新生成、保留并恢复上次流程；
5. 普通界面不要求理解世界书、Embedding、GraphRAG 或提示词；
6. 导入后可直接描述改写目标，批量前必须先试改；
7. 原文和稳定版本不被静默覆盖；
8. 项目一级导航只有正文、规划、设定、检查；
9. 空页面有下一步，错误告诉用户原因和解决办法；
10. 没有无效果按钮；自动化 E2E 覆盖三条入口和恢复。

### Phase 2：InkShadow Model Hub

实施切片：

1. Provider Registry 与首批供应商预设；
2. 一次连接、系统凭据库和普通/专家字段分层；
3. 连通检查、模型同步、目录持久化和可理解结果；
4. 能力证据模型与轻量探测；
5. 小说任务目录、主/备用模型、参数/费用/隐私/失败回退；
6. 智能推荐、高质量、经济、本地隐私、完全自定义方案；
7. 调用事实记录、错误恢复和单能力降级；
8. 迁移、端到端测试和文档同步。

Phase 2 验收：

1. 一个供应商只连接一次，密钥不重复填写；
2. 可测试连接、同步模型并重新同步；
3. 能力来自供应商证据、预设、探测或用户确认，不只猜模型名；
4. 普通用户一键配置方案，高级用户可覆盖；
5. 每项小说任务可选主模型和备用模型；
6. 失败提示可理解，单项能力失败不阻止基础写作；
7. 每次调用记录供应商、模型和任务，但不记录正文、Prompt 和密钥；
8. 旧模型配置无损迁移，旧生成链仍可回退。

### Phase 3：统一故事状态与上下文

交付：统一事实、候选事实、实时人物/世界状态、Embedding/Rerank、分层上下文编译、来源与 Token
说明、可重建索引。

门禁：默认正文生成必须读取已锁定规则、当前任务、POV 知识、近期事件和证据；运行记录可解释
每个上下文项为什么进入或被舍弃。

### Phase 4：小说智能验证

交付：因果事件图、确定性矛盾、世界规则、POV、声纹、多线叙事、伏笔、节奏和质量关卡。

门禁：每个问题有明确类型、原文、冲突事实、证据、严重程度和决定动作；无证据不得报冲突。

### Phase 5：高级 AI 能力

GraphRAG、试演另一条剧情、深度审稿、自动规划、反馈学习、图片和模型评测统一读取 Phase 3–4
状态与证据，不建立平行真相。

### Phase 3 当前验收边界

- 非演示模式的“继续创作”确实运行十二层编译器，不再只发送标题和整章正文；本地演示生成不作为外部调用验收样本。
- 锁定规则和当前任务是必选项；二者超出预算时在模型调用前失败。
- 当前章节、合格 StoryFact、当前版本章节摘要、确认因果候选和启用偏好会进入真实编译；语义资料只在本地 Ollama 向量 ready 时自动加入续写。
- 项目级开关默认关闭。启用后，只有手动保存新版本才会运行章节摘要（最多一次调用）和连续状态提取（人物、世界两条路由最多两次调用）；自动保存不会把正文发送给模型。
- 连续提取只保存带不可变版本、校验值和精确 UTF-16 原文范围的可撤销或待确认事实；重大事实必须确认。严格投影缺字段、越项目/分支、证据失效或权威不足时会跳过并留下诊断，不根据自然语言自行补字段。
- 用户可以在本次生成前查看选择/舍弃、来源和估算用量，也可以在“设定 → AI 参考记录”浏览最近 50 次不含正文、Prompt 和模型回复的历史记录。
- 远程重排仅在用户明确允许发送候选片段，且百炼北京地域、Workspace、能力、凭据、隐私和费用门禁全部满足时使用 Qwen `/reranks`；否则保留本地确定性排序。该路径只有代码与本地/模拟测试证据，尚未使用真实 Qwen 凭据完成云端端到端。
- 因此“上下文编译与受控状态生产主链路”可验收，“无感全自动长程状态维护全部完成”不可验收。

### Phase 4 当前验收边界

- 有结构化、用户确认且精确证据通过的输入时，检查页会给出问题类型、双方证据、严重程度和处理动作。
- 缺证据时明确返回 `skipped`，不能把空结果写成通过。
- 检查只读；忽略/允许/更新设定通过 StoryFact 决定记录，不静默修改正文。
- 声纹、POV、多线和节奏的确定性路径可读取严格投影形成的结构化证据；缺失或不合法投影仍会明确跳过。
- “AI 模糊复核”和“AI 内容质量建议”与确定性结果分栏显示。只有当前保存版本、确认事实/台词等白名单证据、Model Hub 路由，以及文本生成和结构化输出能力都满足时才调用模型；返回必须通过严格 JSON、精确证据 ID 和调用后复核。
- AI 复核只读且全部标记为需要人工判断。未运行、证据不足或返回无效都不会显示为通过，也不会自动修复正文或设定。

### Phase 5 当前验收边界

- What-if 必须先固定因果影响范围，模型不能引用范围外事件，结果只能进入沙盒分支。
- 写作偏好可见、可改、可停、可删、可清空；系统只依据显式重复意见形成偏好，不暗中分析正文。
- 本地模型评测只代表两条基础指令/结构探针和延迟，不代表文学质量。
- 多 Agent 仍是默认关闭的高级工具；统一上下文已接入不等于每次写作都会运行所有 Agent。
- 大纲页已有按需运行的“AI 剧情规划”：可生成全书方向或章节场景拆解，先保存为可编辑、可拒绝的规划建议；明确采纳时只更新目标大纲节点简介，并用基线修订阻止覆盖并发修改。它不是自动后台规划器。
- 图片生成只在桌面端、有效 `image_generation` 能力证据、ready 连接、隐私确认和
  OpenAI-compatible 协议同时满足时开放；当前只安全另存 base64 PNG，不自动写入正文或素材库。

### 跨阶段体验与外部验收边界

- 设置页提供“跟随系统、浅色、深色”三态外观，本机记忆选择并在 React 挂载前应用；这不涉及正文、数据库或云同步。
- 启动、登录与三条创建旅程等无壳页面已在视口内独立滚动；窄窗口下使用安全居中，避免顶部或底部主操作被裁掉。
- 涉及外部模型的连续提取、摘要、远程重排、模糊复核、内容质量、剧情规划和图片生成，均要求用户自行提供有效凭据并完成相应 Model Hub 配置。没有凭据或真实服务时，只能验收失败关闭与本地降级，不能写成真实供应商已验证。
- 单元、组件、Rust 模拟协议和构建测试不能替代百万字级项目的召回率、延迟、内存、费用和长期稳定性测试。
- 发布安装包仍需在目标 Windows 环境完成首次安装、启动、升级、卸载保留、重装、数据库迁移和恢复演练；未完成前不得把工作树测试写成安装包验收通过。

## 2. 质量门禁

每个切片都必须通过：

- 领域/仓库单元测试；
- React 组件和路由测试；
- SQLite 新库、旧库升级、迁移失败回滚测试；
- Typecheck、lint、格式和边界检查；
- 桌面 release Web 构建与 E2E；
- 候选不覆盖、版本恢复、崩溃恢复和密钥不落库专项回归；
- 文档与实际页面、文件、接口同步。

## 3. 主要风险与控制

| 风险                                   | 控制                                                                         | 回滚                                              |
| -------------------------------------- | ---------------------------------------------------------------------------- | ------------------------------------------------- |
| 新导航让旧功能不可达                   | 保留历史 URL；专家模式提供高级工具索引                                       | 恢复旧导航配置，不回滚数据                        |
| 自适应流程中断或丢失                   | 每次动作修订保存；启动时恢复                                                 | 回退到旧九步构思并保留旅程快照                    |
| 导入分析误判                           | 原文版本权威、候选提取、边界复核                                             | 删除派生分析，原文不动                            |
| 试改/批量改写覆盖原文                  | 只写 `ai_candidates`，接受时做基线冲突检查                                   | 拒绝候选或恢复历史版本                            |
| 供应商接口变化                         | 版本化预设、重新同步、能力证据过期                                           | 切到自定义兼容连接或备用模型                      |
| 手动保存触发模型产生意外费用或正文外发 | 项目级默认关闭；界面明确调用次数、路由和费用；自动保存永不调用               | 暂停连续提取/摘要，保留已保存正文与可治理派生事实 |
| 模型投影把推测误作检查证据             | 精确版本证据、严格字段/主体/分支/权威门禁和 fail closed 诊断                 | 停用提取；废弃候选事实并从当前版本重新识别        |
| 远程重排协议或地域变化                 | 只允许已验证的百炼北京 `/reranks` 合同，发送前复核能力、隐私、费用与配置指纹 | 无损降级为本地确定性排序                          |
| 新模型表与旧配置冲突                   | 双读、修订号、迁移收据                                                       | 关闭新 Model Hub 读路径，旧表仍可用               |
| 高级功能拖慢新手链路                   | 后台按需运行，基础写作不依赖高级能力                                         | 关闭单项能力 Feature Flag                         |
| 当前脏工作树隐藏回归                   | 以当前工作树重新跑全门禁，不引用历史 PASS                                    | 保留上一个可安装候选和数据库备份                  |

## 4. 冻结范围

Phase 1 通过前，不扩展 Marketplace、Android、团队版、企业功能、微调和云商业化页面。现有代码不删，
仅停止增加范围。
