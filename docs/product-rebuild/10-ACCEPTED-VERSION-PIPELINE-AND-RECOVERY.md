# 已接受正文的派生资料管线与恢复

> 更新日期：2026-08-08  
> 文档状态：`SUPPORTING_CURRENT`  
> 当前判定：正文安全提交后的派生链、持久任务、启动补跑、人工重试和旧作品当前版本回填已接通；真实云供应商与超大项目仍需外部验收。

## 1. 触发范围

以下动作先完成正文与不可变版本提交，再登记同一类本地任务
`story.accepted-version.process`：

- 编辑器接受 AI 建议版本：`candidate_accept`；
- 导入改写中接受代表段落或逐章建议：`chapter_import`；
- 编辑器或导入流程追加式恢复历史原文：`version_restore`；
- 用户明确点击保存正文：`manual_save`。手动保存一定更新本地搜索和故事关联，章节摘要与
  故事变化识别则继续尊重项目开关；自动保存不进入这条管线，也不会调用模型。

任务元数据只保存项目、章节、稳定版本、触发来源、字符数、四个阶段开关，以及阶段补缺任务所需的
幂等键、规则版本和代数，不保存正文、Prompt、API Key、模型回复或错误原文。任务使用稳定版本 ID
作为幂等键，同一个版本不会重复登记不同工作；旧版没有阶段开关的任务仍按完整管线兼容恢复。

## 2. 执行顺序

`accepted-chapter-pipeline.ts` 依次执行四个互相独立的可重建阶段：

1. 更新本地搜索；
2. 按项目设置尝试更新章节摘要；
3. 按项目设置尝试提取可撤销或待确认的故事变化；
4. 只从合格事实重建故事关联。

任何派生阶段失败都不会回滚已接受正文。没有可用模型或发生临时供应商错误时，模型阶段记录为
明确跳过/失败，不会伪造摘要、事实或供应商结果；只要该模型阶段是任务所要求的，这类真实可恢复
失败就进入 `waiting_retry`，最多三次尝试，不能再以 `succeeded` 掩盖未产出。

模型发送前即可确定的终态不进入重试：空章节、摘要来源过大、绑定版本已经不是当前版本、隐私或
故事状态来源已经变化，以及绑定版本不存在，记为 `not_applicable`。它们只结清当前任务所绑定的
不可变版本，不会为同一版本递增补充代。`CHAPTER_SUMMARY_AUTOMATION_PAUSED` 是唯一当前使用的
`deferred` 策略状态：本任务成功结束且不会自动重试；用户恢复开关后，只有重新查看回填计划并明确
确认，才会登记新的阶段补充任务。

### 2.1 连续故事状态路由完成回执

故事变化阶段对每条实际 Model Hub 路由使用项目、章节、不可变版本和任务组成的持久唯一键。模型派发前
先读取 `continuous_story_state_route_receipts`；已有回执时直接返回已完成，`force`、进程重启或 worker
恢复都不会再次发送正文。只有提交了新的不可变版本，才会产生新的路由工作。即使模型返回零条候选，
完成回执也会保存，避免把“没有变化”误当成“没有执行”。

SQLite 提交会再次校验章节仍活跃、绑定版本仍为当前版本且正文 SHA-256 未变化，然后在同一事务中：

1. 退休相同实体、事实类型和替换键的旧系统临时投影并追加修订；
2. 写入本次合法 StoryFact 与初始修订；
3. 最后写入包含供应商、模型、调用 ID 和候选计数的完成回执。

任一步失败会整体回滚，旧投影不会只退役一半，回执也不会领先于事实。浏览器开发存储通过一次
`localStorage` mutation 提交同等状态。`0052_continuous_story_state_route_receipts.sql` / Tauri `55`
只向前增加该表和来源门禁；`0055_continuous_story_state_historical_route_receipts.sql` / Tauri `58`
允许同项目、章节、不可变版本与内容哈希全部匹配的历史回执随一致性备份恢复，而新提交仍要求当前
版本 CAS。删除作品时回执可随作品级联清理，不阻断正常删除。

## 3. 自动恢复与人工恢复

桌面 Tauri 运行时启动 `AcceptedChapterPipelineWorker`：

- 启动后立即检查一次，之后每 15 秒检查；
- 只执行已到期的重试，或超过 30 秒仍未被前台接手的排队任务；
- 同一进程中的重叠轮询合并为一次；
- 单条损坏或发生竞争的任务不会阻止其他任务；
- 使用独立的到期任务查询按最早到期顺序分页；单轮最多扫描 1,000 条、处理 200 条，
  不再受任务中心“最近 200 条”展示窗口限制；
- 关闭应用时先停止轮询并等待当前安全边界，再关闭备份运行时和 SQLite。

30 秒宽限避免前台刚接受正文时与后台 worker 争抢同一任务。任务仓库的修订/CAS 和租约仍是
最终并发门禁。扫描和处理上限避免一次启动长期占用前台；游标会在后续轮询继续推进，因此也
不能把单轮上限误解为丢弃更旧任务。

任务中心对合法、可重试且元数据完整的该类任务显示“立即重试后台整理”。点击后不会增加一次
额外尝试计数：失败登记时已经进入下一次尝试，`retryNow` 只把计划时间提前到当前时刻。
元数据不完整、类型不匹配或重试次数耗尽时不会显示伪操作按钮。

立即重试不会把页面刚读到的旧失败范围直接带进执行。`retryNow` 用任务序号、尝试次数和当前
`failure.causeCode` 做同一次 CAS，并把规范阶段处置编码成 `pipeline.retry.v2...` 进度标记；标记只含
阶段代码和尝试次数。前台随后只读回刚排队的任务并精确核对完整元数据、序号、尝试和标记，任何后台
抢先执行、再次失败、删除、替换或损坏都会在四个阶段之前失败关闭，也不会意外创建新任务。若进程恰好
在排队后、执行前退出，worker 重启后从同一持久标记恢复失败、`not_applicable` 与 `deferred` 范围，
不会退化为全阶段重复调用；旧 attempt 的标记不能覆盖新状态。

### 3.1 旧作品当前版本回填

旧作品不会在启动时无声扫描或产生模型费用。用户可在章节整理的高级区域先生成只读计划，计划会列出：

- 活跃章节、合格章节、空白章节和不稳定章节数量；
- 已登记与待登记任务数量、涉及字符数；
- 当前项目开启的摘要/故事变化阶段；
- 可能发送给远程供应商的调用上限，以及其中的仅本机章节数量。

计划本身不写数据库，也不调用模型。只有用户在看过计划后明确确认，服务才按稳定版本 ID 幂等登记
`historical_backfill` 任务；登记前会重算计划指纹，章节、版本、隐私、任务或项目开关有变化时整批失败
关闭并要求刷新。回填只处理每章当前、非空、内容校验一致的稳定版本，不遍历也不改写旧历史版本。

为避免旧书一次占满前台，worker 每轮最多执行 5 个历史回填任务，其余任务留在持久队列供后续轮询。
仅本机章节仍可登记派生工作，但不会被计入远程模型调用上限。远程路由在发送正文前失败关闭；
配置并验证可用的本地模型后仍可继续，且不能绕过下节的项目级本地模型门禁。

### 3.2 阶段级补缺与失败恢复（规则 v2）

历史回填不再把“存在同版本任务”等同于“四个阶段都已完成”。首个任务继续使用已发布的
`story.accepted-version:<versionId>` 幂等键；只有缺失阶段才登记
`story.accepted-version:<versionId>:backfill:v2:<stage>:<generation>` 补充任务。因此无需新增
SQLite 迁移，已有任务和数据库可原样读取：

- 新任务成功时，以规范 outcome 进度证据精确记录阶段处置。全完成继续写兼容格式 `pipeline.outcome.<stages>`；包含终态时写紧凑格式 `pipeline.outcome.v2.<stage>-<c|n|d>`，其中 `c` 为完成、`n` 为该不可变版本永久不适用、`d` 为等待未来显式重规划。旧 `succeeded` 任务没有该证据时，只保守承认旧契约可证明的本地搜索/因果阶段，模型阶段按缺失处理；
- `not_applicable` 可作为该版本的覆盖证据，历史回填不会逐代重复补建；`deferred` 不算覆盖证据，但同一任务也不会进入自动重试。只有后续显式计划和确认可以补建延期阶段；真正 provider unavailable/临时失败仍保留可重试语义；
- 原先关闭的摘要或故事变化开关后来开启时，只补对应阶段；普通 candidate/import 任务的模型 unavailable/skip 不再写成成功证据；
- 新任务失败时，安全的 `failure.causeCode` 保存失败阶段掩码；同一任务重试及后续补充任务都跳过已经成功的阶段；
- 同轮同时出现终态/延期与可重试失败时，紧凑 v2 failure evidence 会把失败、`not_applicable`、`deferred` 三组处置一起持久化；普通 progress 在失败转换中被清空也不会丢失处置。最终耗尽后 `c/n` 仍算覆盖，`d` 仍算缺失并等待下一次显式确认；
- 重试耗尽后仍保留阶段掩码；失败或取消的补充任务使用下一代确定性键恢复，不覆盖旧审计记录；
- 无阶段掩码的旧终态失败任务按当前所需阶段保守补缺。章节摘要会先检查当前版本已有结果；连续故事状态则在任何模型派发前检查持久路由回执，重启和强制重试不会重复调用，新的不可变版本才形成新路由工作；
- 排队、运行、等待重试或暂停的阶段视为已经登记，不会并发创建第二条相同工作；历史任务仍受 worker 单轮最多 5 条约束；
- 计划指纹纳入章节/版本/内容/隐私修订、项目开关、任务序列/状态/失败掩码以及补充任务代数，登记前继续执行只读重算和 CAS 防护。
- 每条实际登记前再次核验章节修订、隐私修订、当前版本、正文校验值、项目开关和任务权威。首次写入前重算已过期时整批返回 `stale` 且零写入；批处理中已有项目登记后再过期则返回保留已登记计数的 `partial`；相同权威任务恰由并发方先写入时计入 `alreadyRegistered`，不误报失败。
- 上述复核是“入队前校验”，不是跨章节库与任务库的原子锁。复核通过后、任务真正写入前仍有极短竞态窗口；若作者恰在该窗口保存新版本而旧任务成功写入，本次“登记”回执可以准确为 `completed`，因为请求的审计任务确已登记，不能伪称 `stale`。执行时摘要和故事状态会在模型发送前再次校验当前版本/隐私，以 `not_applicable` 结清旧版本且保持模型网关 0 调用；本地搜索只收录项目当前正文，因果投影只读取当前正式、已确认、未废弃的权威事实。任何阶段都不能回滚或改写已接受正文。
- `runSearch`、`runChapterSummary`、`runStoryState`、`runCausalProjection` 全为 `false` 的空范围任务在直接执行、登记和 worker 恢复三处均失败关闭，不会生成空 outcome。

批量登记现在返回 `completed | partial | stale` 回执。若中途某条登记失败，已创建或并发登记的数量不会丢失；
回执会分别给出尝试、成功登记、新建、并发已登记、失败和剩余任务数，界面显示“部分现有章节任务已登记”，
不会把已经成功的登记误报为“一个都没有登记”。

## 4. ProjectSeed 进入真实续写上下文

三条创建旅程保存的 `ProjectSeed` 不再只是恢复表单。真实续写会读取项目当前 Seed，并只把
作者已确认且非空的字段转换为可追踪上下文：

- 禁止项进入必选硬约束；
- 类型、基调、风格、POV 和改写规则进入当前写作任务；
- 人物和关系进入人物当前状态；
- 世界与创作起点进入世界设定；
- 冲突、当前方向和初步大纲进入场景目标。

未确认的导入分析或 AI 推测不会进入生成上下文。每个采用字段在上下文来源和内容最小化 trace
中保留 `project-seed:<field>` 定位、Seed 修订和是否因 Token 预算舍弃的信息；正文和字段全文
不写入 trace。

## 5. 私密章节与安全边界

私密章节受项目级发送前门禁约束。只要项目仍保留任何 `local_only` 章节（项目归档不会解除保护，
回收站中尚未永久清除的记录也仍受保护），所有可能读取全书事实、因果关系、语义召回或其他章节资料的续写、选区改写、规划、深度
审稿、语义复核、连续提取、导入分析和剧情试演都只允许使用已验证的回环本地模型。远程 Rerank
在读取和发送召回内容前就会禁用。

每次操作先取得只含章节 ID、当前版本、章节修订、隐私修订、状态和隐私模式的 authority 指纹；
真正派发前由原生 SQLite `BEGIN IMMEDIATE` 事务重新读取全项目并精确比较。新增/删除章节、版本变化、
归档/回收状态或隐私变化都会使本次调用在发送 0 字后停止。远程 generation、Embedding 和 Rerank
复核成功后创建不含正文的派发租约，并覆盖完整原生网络生命周期；成功、失败、取消、超时或 panic
真正结束后才释放。租约期间只阻止新增/转入 `local_only` 与项目删除，普通正文编辑、版本提交和
自动保存仍可继续。Renderer SQL bridge 无权读写租约；一致性备份即使物理包含租约，恢复也明确不复制。
默认项目导出不包含私密章节；显式包含是独立用户选择。切换为私密只阻止未来发送，不能声称删除
供应商历史副本。

## 6. 2026-08-08 历史聚焦回归证据

- Task Engine：立即重试状态机、尝试次数和非法转换；
- Desktop store：浏览器持久化立即重试和重开恢复；
- Pipeline：全成功、供应商不可用/临时失败可重试、终态/延期处置、规范 v1/v2 outcome、空范围失败关闭；
- Worker：到期补跑、前台宽限、重叠轮询合并、损坏元数据关闭，以及 205 条损坏任务位于
  合法任务之前时仍能在同轮恢复合法任务；
- 页面：任务中心一键重试并实际取得执行租约；
- 进程恢复：立即重试的阶段处置与 attempt 原子持久化，重启后只重跑失败阶段；旧序号、旧 attempt、
  损坏标记和任务缺失均在阶段执行前关闭且不创建残留任务；
- 纵向集成：编辑器接受、导入接受、历史恢复和手动保存都会产生带正确来源的持久任务；
  手动保存关闭模型分析时仍执行纯本地搜索与因果投影；
- ProjectSeed：仅确认字段进入真实 continuation 编译，未确认 AI 推测被排除。
- 连续状态回执：覆盖模型派发前的持久查重、零候选完成、重启恢复、同一事务退休旧投影/写修订/新事实/回执，以及注入唯一键故障后的整体回滚；迁移另覆盖重复键、来源哈希、不可变更新和作品级联删除。
- 上下文 authority：覆盖已失效事实排除、自动章节投影当前版本/哈希校验、替换键唯一当前项、原始正文绝对 UTF-16 定位，以及缺少或不匹配当前 POV 人物/叙事序号时失败关闭。
- 项目隐私：generation / Embedding / Rerank 原生租约、命令 Future 丢弃、协调竞态、跨语言固定指纹、
  项目搜索探针字符串碰撞和空项目重建均有定向回归；
- 历史回填：计划零写入、明确确认、过期指纹、当前稳定版本边界、版本幂等、仅本机远程上限为零，
  worker 每轮 5 条限流、终态不升代、延期只经新计划确认补建，以及 revalidate→enqueue 竞态下
  摘要/故事状态 0 次模型调用、搜索只含新正文、因果只含当前权威事实均有聚焦回归。

2026-08-08 当次新增聚焦回归为 `45/45 PASS`（派生管线、worker、任务页、导入页、编辑器和
关闭顺序），ProjectSeed/上下文聚焦回归为 `26/26 PASS`。这些数字只对应当次测试集合，不替代
完整桌面全量、真实模型和安装包验收。

同日终态/延期修订的初始聚焦回归为 `5 files / 54 passed`；加入立即重试崩溃原子恢复后，当时同组为
`5 files / 55 passed`（管线、worker、历史回填、章节摘要、连续故事状态）。当时 Desktop 全量为
`199 files / 1,282 passed / 1 skipped`，TypeScript 为 `0 error`。这些证据仍不替代真实供应商与长篇压力验收。

## 7. 尚未宣称完成

1. 自动保存不会调用模型；当前不是无感扫描整本小说的长期守护进程；
2. 历史回填只选择每章在计划及逐项登记前核验为当前的稳定版本，不追溯所有旧版本，也不会自动开始；登记复核不是原子锁，极短竞态产生的旧任务依靠执行前版本/隐私门禁以终态结清，登记成功与来源随后过期并不矛盾；
3. 没有真实商业凭据时，只能验证本地跳过、门禁和模拟协议；
