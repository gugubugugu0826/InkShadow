# 新旧信息架构与核心用户流程

> 文档状态：`AUTHORITATIVE_CURRENT`  
> 应用版本：`0.2.3`；设计基线：`DESIGN v0.3.1b`  
> 本文定义普通用户信息架构和目标流程；实现与验证状态另见 `06`、`08` 和 `docs/execution/`。

## 1. 新旧信息架构对比

| 层级         | 旧结构                                                 | 新结构                                                    |
| ------------ | ------------------------------------------------------ | --------------------------------------------------------- |
| 首屏         | 本地开始、导入/恢复，再进入项目管理                    | 最近创作 + 从一个想法开始 + 导入小说 + 专业创建           |
| 全局导航     | 项目、社区、构思、任务、团队、设置                     | 开始、作品库；设置作为辅助入口，任务改为状态入口          |
| 项目一级导航 | 工作区、搜索、大纲、治理、素材、图谱、抽取、多智能体等 | 正文、规划、设定、检查                                    |
| AI 入口      | 分散在编辑器、构思、图谱、审查、设置                   | 统一 AI 创作助手，根据当前任务切换能力                    |
| 模型入口     | 模型中心 + 技术参数 + 七类角色                         | Model Hub：连接供应商、自动发现、方案、小说任务、高级设置 |
| 高级能力     | 普通导航直接展示                                       | 默认隐藏；从对应用户任务或专家模式进入                    |

| 用户页面   | 目标路由                                        | 兼容策略                                           |
| ---------- | ----------------------------------------------- | -------------------------------------------------- |
| 创作首页   | `/start`                                        | `/` 保持进入此页                                   |
| 从想法开始 | `/create/idea`                                  | 旧 `/ideation` 暂保留为专业九步构思                |

| 作品库     | `/projects`                                     | 保留项目归档、回收、恢复和搜索                     |
| 正文       | `/projects/:projectId` 与章节编辑路由           | 复用章节、编辑器、版本和候选机制                   |
| 规划       | `/projects/:projectId/outline`                  | 页面语言改为故事方向、大纲、场景、剧情线和伏笔     |

## 3. 流程 A：从一个想法开始

### 3.1 主路径

1. 用户点击“从一个想法开始”。
2. 用户输入一句话；项目名、题材和其他字段都不是前置条件。
3. 系统在三个隔离槽中分别生成即时行动、人物对话和悬念线索开头；每槽独立成功、失败、补全或重试。
4. 用户明确选择一个可用开头，或选择自己写/本地示例；未选择前不进入提问。
5. 状态机根据原始想法、已选开头、ProjectSeed 和可证明的现有文本执行一次确定性缺口规划；一次生成最多 3 个核心问题，信息充分时为 0–2 个；支持跳过、返回和随时结束。
6. 后台逐步形成类型、基调、人物、关系、世界、冲突、风格、POV、禁止项、剧情方向和初步大纲。
7. 用户点击“保留并继续”后，系统原子创建项目、第一章、初始大纲和已确认设定。
8. 开头进入“AI 建议版本”；只有用户接受后才成为第一章正式正文。

### 3.2 状态机原则

- 每次屏幕只显示一个主问题和一个主操作。
- 一次规划按“尚缺且最影响下一段创作的信息”确定 0–3 个问题，不强制固定九步顺序。
- 页面持续显示第 N/M 问、完成百分比和剩余问题，让作者知道边界和终点；M 在这次规划后固定，不会因回答增长。
- 用户回答可以同时填充多个弱候选，但只有当前问题被明确确认。
- 回答和跳过都会减少剩余问题；回答不会追加问题，也不会触发第 4 次 AI planner 调用。作者可以随时结束并创建。
- AI 推测不得成为正式事实。
- 流程状态、问题、回答、建议版本和最后活动时间必须可恢复。
- 回答只更新 ProjectSeed，不自动反复重写开头；计划完成后只有作者明确选择时才执行一次整合重写。
- 模型不可用时仍允许本地写作，明确说明如何连接 AI，不伪造模型结果。

## 4. 流程 B：导入小说继续写或改写

1. 本地安全预检 TXT、Markdown、DOCX、EPUB、PDF；首轮沿用已有格式，EPUB 作为新增解析器交付。
2. 用户检查章节边界、标题、解析警告和原文摘要。
3. 系统原子创建只读来源快照与可编辑项目，原文件摘要和校验值可追溯。
4. 分析章节、人物、关系、世界、时间线、POV、风格、事件、伏笔和当前剧情；结果先是候选。
5. 用户用自然语言描述目标，或选常用目标。
6. 系统选择一段代表性文本，只生成一份试改建议。
7. 页面并排显示原文、AI 版本和差异；用户反馈改动大小、对话、描写、节奏或自定义意见。
8. 系统形成可编辑改写规则。
9. 用户确认规则后才启动逐章任务；每章独立产生 AI 建议版本。
10. 用户可逐段/整章接受、拒绝、重新生成、恢复原文或另存版本。

批量改写永远不得直接更新 `chapters.content`。

## 5. 流程 C：专业创建

专业创建允许预先配置世界、人物、关系、时间线、规则、大纲、章节、POV、风格样例、禁止项、
AI 分工、上下文和自动检查，但第一屏只要求项目名。其他部分按“推荐配置”和折叠分组逐步披露。

## 6. 项目工作区

### 正文

- 左侧可折叠章节列表；中间正文；右侧可折叠 AI 创作助手。
- 顶部只保留保存/版本状态和一个动态主按钮。
- AI 建议版本、Diff、接受、拒绝、撤销和版本历史沿用现有安全底座。

### 规划

- 故事方向、大纲、场景、剧情线、未回收伏笔、下一步建议。
- 技术性的图谱和检索细节不作为默认信息。

### 设定

- 人物、世界、关系、事件、时间线、硬规则、AI 当前记住的内容。
- 显示“本章识别到 N 项变化，其中 M 项需要确认”，避免逐条弹窗。

### 检查

- 矛盾、POV 越界、人物声纹、世界规则、节奏、重复剧情、多线失衡和未解决问题。
- 每个问题必须带当前原文、冲突事实、证据、严重程度和可执行动作。
