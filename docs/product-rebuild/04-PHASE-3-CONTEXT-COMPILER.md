## 2. 固定十二层顺序

`packages/ai-core/src/context-compiler.ts` 的顺序为：

1. 锁定硬规则；
2. 当前任务；
3. 当前场景目标；
4. POV 人物已知信息；
5. 人物当前状态；
6. 最近事件；
7. 相关因果链；
8. 未回收伏笔；
9. 世界设定；
10. 人物语言样例；
11. 语义检索；
12. Rerank 补充。

编译结果为每条候选记录：

- 固定层级和评估顺序；
- 选择原因；
- 来源类型、来源 ID、可选版本、定位、内容哈希和证据；
- 估算 Token；
- 是否采用；
- 因预算舍弃时的稳定原因；
- 选择前后的剩余预算。

锁定硬规则和当前任务是必选层。缺少当前任务会返回
`CONTEXT_REQUIRED_LAYER_MISSING`；必选内容超过预算会返回
`CONTEXT_REQUIRED_BUDGET_EXCEEDED`，不会静默丢弃。

## 3. 续写链路的真实来源

当前非演示续写按以下方式组装：

1. 当前任务由运行时显式创建，并绑定当前章节版本；
2. 当前章节正文作为最近连续性来源，最多保留尾部 12,000 个字符；定位始终使用原始正文绝对 UTF-16 起止/总长并携带当前版本内容哈希；当前版本的合格章节摘要也可作为可撤销的最近事件资料；
3. StoryFact 适配器只接收符合状态、分支、确认和证据规则的事实；
4. 锁定正式事实进入第一层，其他事实按类型映射到场景、POV、人物状态、事件、伏笔、世界或声纹层；
5. 写作偏好面板中已启用的偏好作为当前任务补充，最多取 24 条；
6. 已验证主线因果图按当前章节尾部或标题查询相关事件，最多取 8 条；
7. 仅当搜索诊断显示目标是 `local_ollama` 且向量能力 ready 时，取最多 6 条语义候选；
8. 对同一批合格搜索结果先执行 `local_evidence_v1` 确定性重排；仅当用户在专家分工中明确允许发送候选片段，且百炼北京 Qwen 的协议与全部安全门禁通过时，使用远程重排补充顺序，最多追加 4 条第 12 层资料；
9. 编译预算当前固定为 7,000 个保守估算 Token；
10. 编译后的消息进入 Model Hub `continuation` 路由；若未配置该路由，仍可走保留的旧模型配置兼容路径。

远程 Embedding 可以由用户在搜索页明确确认后重建索引，但不会在普通续写时被悄悄调用。
这项限制是隐私边界，不是功能故障。

### 3.1 项目级仅本机 authority

上下文编译可能读取全项目 StoryFact、因果关系和语义候选，因此不能只检查当前目标章节。每次
编译前先取得一个不含正文的项目隐私回执，绑定仍保留的章节 ID、状态、当前版本、章节修订、
隐私修订和隐私模式。只要其中任一章节为 `local_only`：

- 续写、选区改写、规划、审稿、语义复核、连续提取、权威提取和 What-if 只允许已验证的回环本地模型；
- 远程 Embedding 的索引批次和查询向量都停止，远程 Rerank 在发送候选片段前禁用；
- Model Hub 与旧兼容网关都必须在真实网络调用前的最后一个异步边界后，再比较完整 authority 指纹；
- 章节新增、回收、版本、正文修订或隐私修订变化都会使本次调用在发送 0 字处停止并要求重新运行。

项目归档不会解除该保护，回收站中尚未永久清除的章节也继续参与指纹。这个保守门禁会牺牲
部分远程便利，但避免私密章节的派生事实、因果边或检索片段经另一标准章节间接出站。

## 4. StoryFact 门禁

`story-context-source-adapter.ts` 不会把“数据库里存在”当作可发送条件：

- 主线只读取用户确认、正式、未废弃且无需复核的事实；
- 用户确认并锁定的正式事实成为必选硬约束；
- 待确认、废弃、已设置失效位置、其他分支、待复核和无法安全表达证据的事实会被排除；
- 临时事实默认排除；仅允许受策略白名单约束的 system 可重建/可撤销投影进入，而且章节证据必须同时匹配当前版本和 SHA-256；
- system 投影必须携带稳定 replacement key，同一事实类型和 replacement key 只选择一个最新有效项；旧项仍保留可审计的 `deprecated` 修订；
- 当前任务必须由调用方显式提供，不能从模型输出猜测；
- 分支事实不会混入主线续写；
- 来源章节、不可变版本、UTF-16 定位、locator、哈希和摘录会随候选进入本次编译结果。

因此，某一层为空不代表系统忘记了资料，也不代表检查通过；它可能表示尚无满足门禁的结构化证据。

### 4.1 POV 注入边界

`character_knowledge` 等派生 POV 事实除取得事件、来源事实、人物、知识键、信息 ID 和原文证据外，
还必须由调用方同时提供当前 POV 人物和当前叙事序位。编译器只选择同一人物、已经取得且仍落在
`effectiveRange` 内的知识。缺任一字段、人物不一致或序位越界都会以稳定舍弃原因进入审计，不会猜测。

当前生产续写没有可无歧义读取的“当前场景 POV + 叙事序位”作者确认元数据，因此默认保持
fail-closed，派生 POV 层不会注入。ProjectSeed 中的 POV 风格说明仍可作为作者确认的当前任务资料，
但它不等于人物知识边界。必须先补普通用户可确认的场景元数据入口，才能宣称默认 POV 层闭环。

## 5. Embedding 与 Rerank 的准确边界

Embedding 是第 11 层补充，不替代硬规则、任务、POV、人物状态、最近事件或因果链。

当前自动续写只使用本地 Ollama 向量：

- 不会因用户曾配置远程 Embedding 就在续写时自动上传正文；
- 本地向量未 ready、搜索失败或没有合格命中时，其他层仍可继续工作；
- 当前章节当前版本会从语义候选中排除，避免重复注入。

第 12 层先以本地确定性规则根据查询词项、短语、检索分、重要度和固定状态排序，并给出选择
原因。远程路径当前只允许阿里云百炼北京地域的 Qwen OpenAI-compatible `/reranks` 协议：

- 路由必须由用户配置并明确 `cloud_allowed + remoteContentConsent`；
- 连接必须 ready，Workspace、API Key、`rerank` 能力证据、隐私/保留/训练政策和费用上限必须可核验；
- 调用前后复核路由、连接、目录、费用和能力证据指纹；
- 若项目仍保留仅本机章节，候选片段不进入远程重排；否则也要在原生 `rerank` 前最终复核项目 authority；
- 只发送有界查询和候选片段；凭据从 OS 凭据库读取，调用账本不保存内容；
- 未启用、门禁不满足或远程失败时，完整保留本地确定性排序，不会丢失候选。

该路径已有代码、Rust 协议和本地/模拟测试，但尚未使用真实 Qwen Key 做线上端到端；也不能
外推为自定义 Rerank path 或其他供应商已经可用。

## 6. 发送前预览与内容最小化审计

编辑器的续写预检显示：

- 哪些资料会发送；
- 哪些资料因预算或门禁未采用；
- 来源类型和选择原因；
- 已用/总预算 Token。

`0034_context_compilation_trace.sql`（Tauri 迁移版本 `37`）和
`context-compilation-trace-store.ts` 保存不可变编译记录。调用模型前必须先保存 trace；
保存失败时返回可操作错误，正文和已有 AI 建议版本不改变，模型也不会被调用。

`0047_context_compilation_exact_provenance.sql`（Tauri 迁移版本 `50`）以前向追加方式把
trace 精确关联到实际网关 `generationId`、受治理 `ai_generation_runs`、Model Hub 调用事实和
最终隔离的 `ai_candidates`。Model Hub 关联在正文发送前写入；写入失败时发送 0 字。正式桌面版
通过 `SqliteContextTraceOutputCommitUnitOfWork` 在同一 SQLite transaction 中同时写入 ready
Candidate 与输出关联；任一写入失败会整体回滚，不会留下可接受但无法追溯的建议版本。受治理
续写同时通过 generation run 复核。浏览器开发模式沿用现有 localStorage CandidateStore，并明确
标记为 compensating 实现；正式 Tauri 构造会拒绝任何非 `sqlite_atomic` 实现，不会静默回退。
编译器输入条目在代码中明确命名为 `contextCandidateId`，不得当作 AI Candidate ID。

trace 只保存项目/章节/任务、预算、采用与舍弃统计，以及来源 ID、版本、定位和内容哈希。
它不保存正文、Prompt、候选内容、证据摘录、Embedding 或向量。SQLite 与浏览器开发存储
执行同一验证合同，损坏记录会 fail closed。

当前 store 支持按 ID、项目和最终 AI 建议版本读取。“设定 → AI 参考记录”会列出最近 50 次调用的
任务、时间、采用/舍弃数量和预算，并在用户选择后加载逐条来源、层级和舍弃原因。页面仍不
显示正文、Prompt、模型回复或向量；存在精确输出关联时会显示“已精确关联 AI 建议版本”。

## 7. 失败与重试边界

- 必选层缺失或超预算：阻止生成并说明应检查正式设定或预算；
- StoryFact、因果图或本地检索不可用：相应可选来源降级为空，不改动章节；
- trace 无法保存：阻止外部调用；
- ready Candidate 或其输出关联无法原子提交：两者均不落库，稳定正文和已有建议版本不改变；
- 预检后章节版本改变：以 `BASE_VERSION_CHANGED` 阻止旧上下文继续生成；
- 重试会重新准备当前章节和上下文，不把旧编译结果当作新的权威状态；
- 模型输出始终先进入 AI 建议版本，不直接覆盖正文。

- AI Core：层级顺序、必选层、预算、舍弃原因和来源追踪；
- Data：`0034` 内容最小化 trace、`0047` 精确生成/调用/输出关联、`0052` 连续提取路由回执、`0055` 合法历史回执恢复约束、不可变约束和备份恢复；真实
  SQLite 故障注入覆盖 Candidate INSERT 后、输出关联写入前失败的整笔回滚，以及完全相同重试
  的幂等去重和同 ID 不同内容的冲突关闭；
- Desktop：StoryFact/章节摘要适配、本地语义候选、本地与百炼/Qwen 远程重排、因果候选、写作偏好、运行时接线、编辑器预览和上下文历史面板；
- 安全回归：远程 Embedding 不隐式调用、trace 与调用关联先于正文发送、章节版本变化阻断、
  Candidate 隔离、按最终 Candidate 精确反查，以及原子提交失败时稳定正文不变且不存在 ready Candidate。
