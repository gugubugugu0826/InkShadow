# Phase 5：图片生成最小真实闭环

> 文档状态：`SUPPORTING_CURRENT`  
> 当前源码目标版本：`0.2.4`；最近已发布版本：`0.2.3`；页面与模拟协议测试不代表真实图片供应商已验收。

更新时间：2026-08-08

## 当前实现边界

InkShadow 已实现一个可验证的图片生成闭环，但不会把“模型目录里存在某个名称”当成能力证明。

只有同时满足以下条件的模型才会开放生成入口：

1. Model Hub 的 `image_generation` 任务已配置；
2. 目录条目当前可用、未弃用、未过期；
3. `image_generation` 能力存在尚未过期的 `supported` 证据；
4. 供应商连接已通过测试；
5. 凭据、数据去向和隐私证据完整；
6. 当前连接明确使用 OpenAI-compatible 协议。

模型名称不会参与能力判断。Anthropic、Gemini、Ollama 等尚未实现的图片协议会明确显示为“不支持”，不会伪造结果。

## 真实调用协议

原生网关调用连接根地址下的 `POST /images/generations`，请求仅包含：

```json
{
  "model": "<Model Hub 实际选择的模型 ID>",
  "prompt": "<用户单独输入的图片描述>",
  "n": 1
}
```

该最小请求同时避免依赖具体模型名称和模型专属高级参数。当前只接受供应商直接返回的 base64 PNG；临时 URL 不会被自动下载，避免跟随供应商返回的不受信任地址。OpenAI 官方图片接口说明：

- <https://developers.openai.com/api/reference/resources/images/methods/generate>
- <https://developers.openai.com/api/reference/resources/images>

当前将提示限制为 1000 个字符，这是兼容旧图片协议的保守上限；后续只有在能力证据能表达协议版本和参数范围后，才会按模型扩展尺寸、质量、透明背景和更长提示。

## 本地保存与内容安全

1. 检查结果为实际连接、目录模型、任务分工、能力证据、隐私/费用策略、数据去向和非秘密凭据身份生成 SHA-256 确认指纹；
2. 用户确认费用与数据去向，生成提交必须携带刚才看到的指纹；
3. 服务在创建调用记录前、原生网关派发前各复核一次；任一字段变化都会要求重新检查，网关调用为 0；
4. 系统先打开原生保存对话框；
5. 用户取消时不会调用模型，也不会创建调用账本记录；
6. 保存选择被转换为五分钟有效、单次使用的随机票据，WebView 不会取得完整路径；
7. 只允许选择尚不存在的 `.png` 文件，不覆盖已有文件；
8. 原生端重新检查父目录身份，拒绝目录替换和票据重放；
9. 响应经过 base64、PNG 签名、尺寸和体积校验后才写入；
10. 图片不会自动写入正文、设定、素材库或 Candidate；
11. 写入失败会清理本次创建的不完整文件。

## 调用账本

每次实际调用记录：

- 任务：`image_generation`；
- 实际供应商连接；
- 实际目录条目和模型 ID；
- 主模型或预调用备用模型；
- 数据去向；
- 成功、失败和供应商错误码；
- 供应商返回时的输入、输出 Token 用量。

账本不记录图片提示、API Key、Base URL、目标路径、目标票据、图片字节或供应商响应正文。

图片通常按张、尺寸和质量计费，现有统一账本没有可靠的逐张价格字段。因此界面明确提示“无法审计逐张价格”，不会把文本 Token 价格冒充图片价格；如果任务设置了当前无法验证的硬费用上限，调用会在发送前被拒绝。

## 后续扩展条件

以下能力不能仅靠增加按钮完成：

- 其他供应商图片协议；
- 图片编辑和参考图输入；
- 任意尺寸、质量、格式和透明背景；
- 逐张价格硬上限；
- 素材库管理和正文插图引用。

继续扩展前，需要让能力证据结构能够记录图片协议版本、输出传输方式、参数范围和可验证的价格单位。
