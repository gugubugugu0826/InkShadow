# Phase 3：统一故事状态库

> 实现日期：2026-08-01  
> 最近复核：2026-08-08（当前工作树）  
> 文档状态：`SUPPORTING_CURRENT`  
> 当前判定：StoryFact 生命周期、手动保存后的受控连续提取、严格投影和主要读取链路已闭环到当前条件范围；无感后台全书维护仍未完成。

## 1. 当前结论

InkShadow 已建立统一的 `StoryFact` 权威层，并实际接入开书、专业创建、导入分析、故事设定、
因果图、续写上下文、小说检查、What-if 和深度审稿。旧正式设定、旧记忆和旧 GraphRAG
仍保留为兼容结构，不会被迁移脚本覆盖。

这里的“已接入”不代表系统已经能从任意自然语言正文自动维护完整故事状态：

- 用户在“一句话开书”和“专业创建”中明确给出的设定，可以直接创建为用户确认的正式事实；
- 导入分析得到的事实一律是待确认候选，不能自动提升为正式事实；
- 项目级开关启用后，手动保存新版本可以运行人物/世界两条提取路由，生成有精确原文证据的可撤销或待确认变化；自动保存永不调用模型；
- 跨章节实体只在候选别名能唯一命中用户已确认实体时保守合并；歧义别名会保留为需要复核的新候选，作者只能从证据允许列表选择已有对象或明确保留独立对象，完成消歧前不能确认；
- 可选验证、POV、声纹和叙事投影会经过独立严格适配器再次核验，缺字段或证据/权威不足时不会进入下游检查；
- 只有满足状态、分支和证据门禁的事实，才能进入因果投影、上下文或检查。

因此，本层的准确描述是：

> 统一事实的安全存储、受控生产与严格消费链已经存在；自动保存驱动、后台全书扫描和完整长期维护尚未完成。

## 2. 可复用结构与兼容边界

| 结构/服务                                          | 当前用途                                       | 边界                                                      |
| -------------------------------------------------- | ---------------------------------------------- | --------------------------------------------------------- |
| `projects`、`chapters`、`chapter_versions`         | 项目归属、正文与不可变版本，是章节证据的权威源 | 不等同故事事实库                                          |
| `story_formal_records`                             | 兼容旧人物、世界规则、伏笔和时间线正式记录     | 不自动视为新正式事实；只能显式回填为待复核事实            |
| `story_review_items`、`authoritative_extraction_*` | 保留旧抽取、评审和人工决定链                   | 不绕过 StoryFact 的确认与证据门禁                         |
| `story_memory_*`                                   | 保留旧 L1–L4 记忆治理和兼容读取                | 记忆不是正式事实；可显式回填为待复核事实                  |
| `story_what_if_branches`                           | 保留旧 What-if 兼容数据                        | 新因果 What-if 结果使用 `status=branch` 的 StoryFact 隔离 |
| `graph_rag_*`                                      | 保留可重建的旧图检索投影                       | 不是统一事实权威源；不能覆盖确认事实                      |
| 大纲、素材和搜索索引                               | 规划、资料和可重建检索来源                     | 不因存在于索引中就成为已经发生的事实                      |

## 3. 已实现数据结构

本地迁移：

- `packages/data/migrations/0032_unified_story_facts.sql`；
- Tauri/SQLx 迁移版本 `35`；
- 已发布的更早迁移未被修改。

### 3.1 `story_facts`

每条事实至少保存：

- `fact_type`；
- `content_text` 和/或 `value_json`；
- `source_kind`、`evidence_reference`；
- 可选章节、不可变版本、UTF-16 起止位置、原文长度和精确摘录；
- `effective_at`、`invalidated_at`；
- `branch_id`；
- `confidence`；
- `status`：`formal`、`temporary`、`unconfirmed`、`deprecated`、`branch`；
- `origin`：`user`、`ai_extraction`、`import`、`legacy`、`system`；
- 用户确认、锁定、废弃、需要复核、确认人和确认时间；
- 修订号、创建和更新时间。

### 3.2 `story_fact_revisions`

创建、确认、治理更新和废弃都会产生不可变快照。事实内容、类型、来源、证据、时效和分支
不能借普通治理动作原地改写；需要修正内容时，应创建新事实并废弃旧事实。

### 3.3 `story_fact_legacy_links`

新事实可以稳定链接到旧 `story_formal_records` 或 `story_memory_records`。
“旧记录 + 旧修订号”唯一约束让回填幂等，同时保留旧表和旧记录原值。

## 4. 状态与更新策略

`storyFactUpdatePolicy` 把更新分成三组：

| 分组         | 当前类型示例                                                          | 行为                                               |
| ------------ | --------------------------------------------------------------------- | -------------------------------------------------- |
| 可重建       | 章节摘要、节奏指标、分析标签、搜索索引标记                            | 可以由系统重新计算，不作为重大正式事实             |
| 自动但可撤销 | 人物临时状态、场景标签、普通关系变化、事件归类、弱推测                | 只有安全来源和允许类型才可暂存；必须保留治理与历史 |
| 必须确认     | 人物死亡/身份、核心关系、世界规则、重大能力/物品/时间线变化、正式伏笔 | 未经用户确认不得成为正式事实                       |

未知类型默认进入“必须确认”，不会因为模型置信度高而自动放行。当前自动暂存还要求
`origin=system` 且不能命中重大事实策略；导入分析使用 `origin=ai_extraction`，所以始终保持
`unconfirmed + needs_review`。

## 5. 安全不变量

1. AI 推测、导入内容、旧数据和系统推导不能直接插入为正式事实。
2. 正式事实必须有用户确认、确认人和确认时间，且不能同时待复核、废弃或属于分支。
3. 只有正式事实可以锁定；锁定事实会成为续写上下文的必选硬规则。
4. 分支事实必须带 `branch_id`，不能用状态更新原地提升为主线。
5. 废弃是有修订历史的治理动作，不是物理删除。
6. 章节证据必须绑定同一项目、章节和不可变版本；SQLite 路径还会校验原文长度和精确摘录。
7. 治理写入使用修订号比较；并发冲突不会静默覆盖获胜版本。
8. 备份恢复包含事实、修订历史和 legacy link。
9. 正文、章节版本、AI 建议版本和旧故事表不会被 StoryFact 迁移或治理动作改写。

## 6. 已接入的用户与运行时链路

### 6.1 事实产生

- “从一个想法开始”和“专业创建”把用户明确确认的基础设定写成正式用户事实；
- 导入作品分析按章节版本和 UTF-16 原文证据写入待确认事实；
- 用户为项目启用后，手动保存新版本会运行 `character_extraction` 与 `world_extraction`，按更新策略写入可撤销临时事实、可重建系统事实或待确认重大事实；
- “章节摘要与长程记忆”可在手动保存后或用户显式重建时生成当前版本摘要，保存为可重建、可撤销的临时 StoryFact；
- 故事设定页允许用户手工添加正式事实；
- 旧正式记录和记忆只能经显式、幂等回填生成 `legacy + unconfirmed + needs_review`；
- 因果 What-if 只创建 `branch` 事实，不修改主线。

### 6.2 用户治理

“设定”页面可查看正式、临时、待确认、废弃和分支事实，并支持：

- 新增用户确认事实；
- 确认待确认事实；
- 锁定或解锁正式事实；
- 废弃事实；
- 从符合因果结构的确认事实重建故事关联。

普通新增表单目前以“事实类型 + 自由文本 + 是否锁定”为主；它不是完整的结构化人物、
知识边界或因果关系编辑器。

### 6.3 事实消费

- 分层上下文编译器只读取合格主线事实，并把锁定事实放在最高优先级；
- 因果投影只读取确认、正式、主线、未废弃、无需复核且证据可核验的因果事实；
- 矛盾、POV、声纹和叙事分析只在所需结构与精确证据齐备时运行，否则明确显示跳过原因；
- 连续提取的 `inkshadow.continuous-story-state.v2` 可选投影只经严格适配后进入验证、POV/声纹和叙事分析；项目、章节、版本、校验值、UTF-16 范围、分支、当前性、确认/锁定任一门禁不通过都会留下诊断并跳过；
- 深度审稿读取同一组确认 StoryFact 和已验证因果图，提交引用时再次核验。

## 7. 因果投影的关系

迁移 `0033_causal_event_graph.sql`（Tauri 版本 `36`）保存由确认 StoryFact 重建的派生因果图。
事件结构可表达参与者、时间、地点、前置、结果、人物/关系/物品变化、知识变化、伏笔和原文证据；
关系支持导致、依赖、阻止、揭示、误导、发生在之前、改变状态、获得信息和失去物品。

确定性影响遍历不会把单纯的“发生在之前”当作因果传播。图可以重建，不是新的事实权威源。
当前导入分析会生成结构化 `causal_event`，但不会跨章节猜测关系；普通事实表单也不能完整编辑
因果 JSON，所以真实项目若缺少确认关系，影响链可能只包含起点事件。

## 8. 当前验证证据

- Story Core：事实状态机、确认、锁定、废弃、分支和证据合同；
- Data：`0032` 迁移、SQLite store、CAS、修订历史、幂等 legacy 回填和维护备份；
- Desktop：浏览器 store、Tauri 迁移版本 `35`、开书/专业创建/导入/设定页接线；
- 下游：因果投影、上下文、检查、What-if 和多 Agent 的合格事实筛选测试。

这些自动化测试证明当前合同和接线，不替代真实长篇语料、旧库升级安装包和真实用户治理体验验收。

## 9. 仍未完成

1. 自动保存或后台无感扫描全书的持续提取；当前只在项目启用后由手动保存或显式重识别触发；
2. 唯一匹配和人工允许列表消歧已具备；仍缺从全书自然语言自动维护稳定人物 ID、别名历史和高准确率归并；
3. 面向普通用户的完整人物状态、关系、知识边界、剧情线、场景指标和因果关系编辑器；
4. POV 投影已核验何时、通过哪个事件和来源获得信息；仍缺“知道/不知道/怀疑/误信”的完整全书知识状态维护；
5. 从正文可靠识别说话人、对象和跨全书人物台词证据；
6. 从精确证据安全建立因果边；当前连续提取只产生事件/状态类候选；
7. 旧正式记录、记忆和新 StoryFact 的长期统一迁移完成态；
8. 将分支 What-if 结果经审查提升为新主线候选的流程。

上述缺口完成前，不能把 Phase 3 整体标记为“已全部完成”。
