# Phase 0 真实能力审计

> 审计日期：2026-08-01  
> 审计对象：当前仓库工作树  
> 审计方法：文档声明、数据结构、实际调用链、用户可感知闭环和自动化测试五项交叉核验  
> 文档状态：`HISTORICAL` Phase 0 起始快照；不是 2026-08-08 当前 UI 或能力权威

> 本文第 1–6 节保留重构开始时的 Phase 0 历史基线。Phase 3–5 已继续实施，当前判定请同时读取
> [Phase 3–5 真实能力台账](06-PHASE-3-TO-5-CAPABILITY-LEDGER.md)，不得继续引用下表中的旧“待实现”状态
> 代表当前工作树。

## 1. 结论摘要

InkShadow 已经拥有一套值得保留的本地可靠性和 AI 安全编辑底座，但当前产品仍然由项目、
大纲、故事治理、检索、图谱、多智能体、微调和任务中心等系统模块组织。高级小说智能能力中，
大量能力停留在数据结构、派生投影、接口、独立页面或受 Feature Flag 保护的实验链路，尚未进入
“用户写下一段正文”这一条默认调用链。

因此，当前真实定位应当是：

> 已具备可靠本地创作与可撤销 AI 建议机制的工程底座；新手主链路、统一 Model Hub、分层上下文、
> 因果图和小说专用验证闭环仍需重构。

## 2. 分级定义

| 分级     | 判断标准                                                       |
| -------- | -------------------------------------------------------------- |
| 真正可用 | 有真实入口、持久化、失败处理和当前自动化测试，用户能完成闭环   |
| 只有底层 | 有领域对象、表、仓库或运行时，但默认创作流程没有使用           |
| 只有页面 | 页面可打开，但动作依赖缺失、受关闭的开关保护或没有完整结果闭环 |
| 只有接口 | IPC/API/端口存在，但普通用户流程没有接入                       |
| 只有文档 | 只在规划、状态或说明中出现，未找到可执行调用链                 |
| 需要重构 | 有可复用实现，但当前模型与新产品目标冲突                       |

## 4. 当前信息架构问题的代码证据

- `apps/desktop/src/app.tsx` 注册项目、搜索、图谱、抽取、素材、大纲、故事治理、同步、
  多智能体、微调、扩展、团队、模板、任务和设置等大量并列路由。
- `apps/desktop/src/components/desktop-shell.tsx` 把多项技术模块直接放入普通导航，并使用
  “多智能体审查”“微调治理”“权威事实抽取”等工程语言。
- `apps/desktop/src/pages/projects-page.tsx` 以项目生命周期管理为首页中心。
- `apps/desktop/src/pages/ideation-page.tsx` 的快速模式一次要求项目名、类型、主角类型、目标字数、
  创意和可选风格；引导模式是固定九步。
- `apps/desktop/src/pages/editor-page.tsx` 具备强安全机制，但生成预检、模型、费用、候选和版本操作
  同时呈现，默认信息密度过高。

## 5. 测试证据边界

仓库包含大量单元、集成和 E2E 测试，这证明许多局部安全契约已经被认真实现。但审计时工作树存在
大量未提交改动，`playwright/.last-run`、历史发布报告和 2026-07-31 安装包只证明当时的快照，不能
证明 2026-08-01 当前工作树。

后续每个阶段必须重新运行与改动范围匹配的：

- 单元和组件测试；
- TypeScript 类型检查与 lint；
- SQLite 迁移兼容测试；
- 桌面 Web 构建；
- 真实发布构建 E2E；
- 安装包启动、首次体验、恢复和候选安全冒烟。

## 6. Phase 0 决策

1. 保留现有本地数据、版本、恢复、候选、凭据和同步安全结构。
2. 不删除旧高级路由；默认隐藏到“高级工具”，避免破坏书签和兼容性。
3. 新增迁移只能追加版本，禁止修改已发布迁移校验和。
4. 首页和工作区改为用户任务驱动；项目管理降为“作品库”。
5. 所有高级能力按用户可感知闭环重新验收，旧状态标签不继承。
6. Phase 1 完成前冻结 Marketplace、Android、团队和企业能力扩展。
