## 核心能力审计

### 可保留的真实能力

- Candidate 绑定精确基线版本；接受时校验基线归属与哈希。
- 正文、新版本和 Candidate 状态在同一 SQLite 事务中提交，竞态失败回滚。
- 编辑器有未保存正文保护、RecoveryDraft、版本比较、恢复和会话撤销。
- 一句话 Journey 可保存回答、跳过、返回、重生成和恢复状态；首段进入隔离 Candidate。
- Model Hub 支持多连接、系统凭据库、连接测试、模型目录、能力证据、小说任务主备路由及调用账本。
- Context Compiler 能读取稳定正文、已确认 StoryFact、有效摘要、因果候选、写作偏好和范围化本地 FTS，并记录采用/舍弃来源和预算；vector/rerank 只保留可选底层槽，当前无远程 production caller。
- StoryFact、连续状态提取、章节摘要、证据化检查、确认事实因果投影、任务中心、图片生成、手动一致性备份均为真实底座。
- EPUB 导入是真实且具备压缩炸弹、脚本、路径穿越、DRM、CRC 和远程引用防护的实现。

### checkpoint 的关键断点

1. 接受 Candidate 后只完成正文、版本、Candidate 状态和反馈；摘要、状态提取、索引、因果投影和任务中心没有自动接续。
2. 新开书 Journey、导入和专业创建没有共享持久化的统一 ProjectSeed。
3. Context Compile trace 与实际 model invocation、Candidate 之间缺稳定关联。
4. 章节级私密合同不存在；`local_only` 路由不能证明某章云端发送为 0 字。
5. Provider 响应在 checkpoint 时缺非流式正文、`reasoning_content`、截断原因和运行期备用模型处理；GLM 当时未进入 Registry。当前修复状态见“本轮增量”，本句只保留历史判断。
6. EPUB 只有导入没有导出；自动备份、补跑和 30 天清理不存在。
7. 备份恢复白名单遗漏新的 Journey 和部分故事状态表，不能宣称完整恢复。
8. Shell、编辑器响应式、深色正文、命令面板、图标和根错误边界未达到 DESIGN。
