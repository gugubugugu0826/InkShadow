## 1. 本轮产品目标与尚未解除的授权边界

本轮目标是让直接模式提供更少术语、更少入口的完整安全写作链：普通用户选择创作动作后仍会看到隔离结果，并明确决定使用或放弃；专业模式继续提供比较、模型、费用、上下文和完整技术记录。两种模式共用正文、版本、调用记录、本地设定整理和可恢复派生任务。

附件提出“一次点击即授权一次远程生成并自动写入”的新策略，但该附件不是直接执行授权；它也与用户随后直接报告 N-NEW1 时要求“使用这版／放弃”可正常决定结果、以及 N-NEW5 中确认发送前逐次披露的要求冲突。以最新直接指令为准：当前工作树仍要求每次远程发送逐次披露精确服务、模型、范围、次数、费用和隐私，所有生成结果先保持隔离，作者明确选择“使用这版”后才写入正文。因为附件本身被要求与用户的直接指令区分，在用户未作独立明确授权前：

- 不得把“移除续写、开头生成的二次确认”写成已经完成；
- 不得把“一句话开始创作后自动进入正文”写成已经完成；
- 不得读取已保存凭据或执行会产生费用的真实模型调用；
- 其余不扩大外发权限的直接模式、数据保护、中文化和可恢复操作可以继续实现与验证。

若用户随后独立明确授权，上述差异必须作为新的权限与事务设计单独实现和验证；当前文档不得把它混入已经存在的隔离接受链。

## 2. 直接模式从旧流程到目标流程

| 动作             | 旧流程                       | 当前工作树状态                                                                             | 目标结果                                   |
| ---------------- | ---------------------------- | ------------------------------------------------------------------------------------------ | ------------------------------------------ |
| 续写             | 生成隔离结果，查看后接受     | 仍逐次披露并生成隔离结果；明确“使用这版”后才原子写入并可撤销                               | 一次点击授权与自动正文仅是待授权目标       |
| 改写、润色、扩写 | 生成后查看并接受             | 两种模式都先保持隔离，明确使用后才替换或扩展选区                                           | 自动应用仅是待授权目标；失败不留下半段正文 |
| 选择方向         | 可能把方向与正文候选混用     | 方向结果与正文结果已通过用途字段区分；只在点击后生成，严格解析三个方向，支持自定义和换一组 | 点击某方向后立即续写；换一组才再次调用     |
| 从想法生成开头   | 多方案、再选方案、再进入正文 | 直接模式已收敛为单个开头请求；结果仍隔离并等待明确进入正文                                 | 一次点击直达正文仅是待授权目标             |

直接模式不展示路由、追踪和内部存储等专业术语，但仍展示可阅读的隔离创作结果及“使用这版”“放弃”等明确决定。两种模式共用正文、不可变版本、生成运行、调用事实、上下文记录、故事事实和派生任务，不建立第二套存储。

## 3. 隔离结果、明确使用与失败保护

当前实现采用“逐次披露、结果隔离、明确使用后一次提交”的策略：

1. 生成前绑定当前作品、章节、正文版本、选区或光标以及模式。
2. 结果先写入现有隔离结果链，并区分正文结果与方向选项。
3. 失败、取消、模式变化、章节变化或基线版本变化时，不修改正文。
4. 两种模式都等待作者明确选择“使用这版”，再由现有接受事务一次性写入并创建新的不可变版本。
5. 直接模式简化展示，专业模式提供完整比较；二者都不自动接受正文。
6. 后台整理和派生任务失败只影响可重建结果，不回滚已接受正文。
7. 直接操作保存操作前版本；关闭并重新打开后，可从当前不可变版本和接受记录重建撤销入口。

当前工作树已加入统一的“接受章节后事实前检”入口。是否负责本地故事资料整理在接受或保存时写入持久布尔字段；旧记录缺失时安全按关闭处理，后台执行器重启、模式切换和人工重试都不读取执行时的当前模式来猜测。生产本地数据库的隔离结果接受已把正文、版本、结果决定和派生任务登记放入同一事务；其他入口只按代码已实现边界记录，不外推为全部原子登记完成。

## 4. 自动整理设定与用户优先级

直接模式在正文自动保存稳定约一秒后，以已经保存的不可变版本为输入运行确定性本地整理。当前范围包括正文证据、人物、地点、组织、物品、关系、规则、事件、时间线、目标与动机、章节摘要及后续可重建投影的入口。没有真实证据时不得用预设内容或模型外观的假数据补齐。

每条自动事实必须保留来源章节、版本和原文证据；整理失败不得修改或回滚正文。当前用户治理边界是：

- 新增纯文本事实；
- 只有结构化内容为空（数据库字段 `structuredValue = null`）的纯文本事实可以使用通用修改、历史版本恢复和重复事实合并；
- 结构化事实和因果事实不允许通过纯文本编辑、普通历史恢复或通用合并改变结构；
- 结构化/因果事实只开放证据查看、固定、删除和删除恢复等不破坏结构的安全动作；
- 用户删除后的相同自动证据保持抑制；后续确有新正文证据时可形成新的可重建事实；

  这部分的原子回滚、重开持久化、迁移、维护和备份恢复已纳入当前自动化：故事核心包 138 项、数据包 453 项通过。真实历史库升级和安装程序恢复仍未手动验证，因此不标记为真机通过。

## 5. 方向续写

方向选项使用独立用途 `continuation_directions`，正文生成使用 `prose`，避免方向结果被误当正文接受。当前策略是：

- 只有用户点击“选择方向”时才请求方向；
- 每次操作至多一次服务请求，自动重试为零；
- 只接受恰好三个可区分方向，不打分、不推荐；
- 点击系统方向后按该方向续写；
- 自定义方向通过“按这个方向写”触发；
- “换一组”是一次新的显式动作，不在后台刷新；
- 方向失败不改正文，保留重试和自定义入口；
- 不以固定模板或本地假方向冒充服务返回。

## 6. 专业模式保留范围

专业模式继续保留模型中心、服务和模型选择、调用与费用、任务与通知、上下文来源、调用回执、隔离结果预览和比较、接受与放弃、多方案生成、详细错误、追踪诊断和高级创作参数。切换模式只改变界面策略，不删除正文、设定、版本、方向和调用记录。

## 7. 数据与迁移

本轮只追加向前迁移，不修改任何已经发布的迁移或校验值：

- `0072_ai_candidate_purpose.sql`：为隔离结果增加用途，区分正文结果和续写方向；
- `0073_story_fact_user_revisions.sql`：只为 `structuredValue = null` 的纯文本事实补充修改、恢复与合并记录；
- `0074_chapter_version_story_fact_responsibility.sql`：把“是否负责本地故事资料整理”冻结在每个不可变章节版本上；历史版本安全默认为关闭，后续不得随当前模式漂移；
- `0075_generation_attempt_privacy_snapshot.sql`：为每次新生成尝试保存隐私快照版本、隐私策略、数据去向和同一次模型调用标识；迁移前旧行保留空值，新行缺失、部分缺失或与绑定调用不一致时失败关闭；
- 当前工作树迁移上限为 Data `0075` / Tauri `78`（75 个 Data migration + 3 个 story-core migration）。

维护与恢复逻辑需要覆盖新字段和用户事实修订；方向建议和其他可重建投影不能成为正文恢复依赖。恢复备份前创建自动的恢复前快照；若快照或恢复失败，原数据保持不变。
