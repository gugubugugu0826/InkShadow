## 三、数据保护与迁移

1. Data `0079_story_fact_evidence.sql`／Tauri `82`：为一条受治理故事事实追加多处不可变正文依据，不覆盖原始来源，不删除历史重复行，也不改变作者已经作出的决定。

两项迁移均未修改任何已发布迁移或校验值。当前自动化已经覆盖新库、连续升级、真实临时 SQLite 关闭重开、旧备份回填、当前备份恢复、外键与不可变守卫。恢复前后的正文、不可变版本、灵感、设定和历史隔离结果由测试守恒；现场数据库未取得，不能把构造数据写成现场恢复证明。

## 六、发布门禁

只有以下条件全部满足，才可继续推送、标签和发布：

1. 从唯一干净提交重新取得完整 `release:check`、正式发布端到端和完整未签名候选链的终局证据；
2. 四项选区技能在真实安装窗口中完成人工选区、真实调用、隔离、放弃、接受、版本和重启闭环；
3. 0.2.12 至 0.2.14 覆盖升级以及安装、卸载、重装和恢复完成；
4. 从唯一干净提交完整运行 `pnpm release:candidate:unsigned`；
5. 五个 0.2.14 附件形成并核对版本、AMD64 应用载荷、签名状态、大小、SHA-256、源码指纹和正式前端指纹；
6. 远端 `main` 和必需持续集成通过，标签、来源清单和 Release 指向同一提交；
7. 发布后从 GitHub 全新下载五个附件并逐项复核。

当前源码构建已经通过固定预算，但干净来源上的正式发布端到端与候选链、真实模型、真人选区、真实安装和真实系统 200% 缩放门禁仍未闭合。因此远端推送、`v0.2.14` 标签和 GitHub Release 继续阻断。任何提交 SHA、安装包大小、摘要、标签或 Release 链接只能在事实产生后写入发布附件和最终报告，本文不预填未知值。
